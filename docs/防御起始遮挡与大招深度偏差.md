# 防御确认与大招起始判定（2026-09-30）

家长反馈防御容易变成普攻，大招保持过程中会被出拳打断。本次基于 `2b23d9d` 修复姿势刚建立和从普攻切换时的可复现问题。

- 防御只确认了一部分时，原计时器已经允许最多 0.20 秒的手腕遮挡，但输入优先级只保护已完成的护盾。现在这段尚未完成的确认也保留防御意图，丢弃遮挡期间不可靠的出拳轨迹。遮挡不增加确认进度，也不提前展开护盾；长时间遮挡和明确放下双手仍取消。
- 已摆出 L 形、但手腕深度从第一帧就估计偏前时，原入口可能一直将它排除。增加清楚可见的前臂作为独立证据：一侧前臂上举，另一侧横放并朝胸前中心收拢，同时仍须满足原有手腕形状。此路径不依赖估计深度，仍需要原来的保持确认、能量和松手重置。原有仅靠手腕的识别路径继续可用，不额外要求肘部一直可见。
- 大招已经在蓄力时，HUD 优先保留对应的保持提示和进度条，避免怪兽预警将引导突然换成防御。

回归在修改前分别失败于防御确认遮挡及首次 L 形深度偏差，记录于 `logs/pose-entry-overlap-before.log`、`logs/pose-entry-depth-before.log`。新增检查覆盖 15／30／60 Hz、两侧手臂、短暂和持续遮挡、单次发射及松手再发；还验证了真正的前伸普攻、水平前臂和不可见肘部不会借用新增 L 形路径。

第一轮完整游戏回放仍出现 3 次误触，失败记录保留在 `logs/pose-startup-guided-check.log` 和 `artifacts/pose-startup/guided`。针对切换过程新增检查，发现出拳后立即收手摆防御时，旧拳尚未脱离冷却中的锁定状态，可以阻止防御参照位置建立。新增回归在修正前复现失败，见 `logs/pose-startup-transition-before.log`。现在明确向胸前收回的二维手臂位移可建立防御参照；这不会提前解除普攻冷却，也不靠深度波动推断已经收手。保持伸出的拳头仍须收回。

继续运行仍有起始误触，保留了 `artifacts/pose-startup/trace/synthetic-poses.jsonl` 供逐帧重放。接收器取最新包，可能跳过最早的完整防御姿势、先读到手腕遮挡帧，此时防御计时还不存在。补充用例在修改前失败于这条路径，见 `logs/pose-packet-gap-before.log`。现在从双手可见变成手腕短暂丢失的前 0.20 秒，也清除跨越这次可见度变化的出拳轨迹；不据此授予护盾。超过该过渡后，可见的单手仍可凭新的轨迹出拳。已有单手出拳、收手再打、正常松手和长时间遮挡退出的检查继续通过。

回放脚本增加 `--gesture-startup-noise`，注入防御确认前的遮挡、大招第一帧起的深度偏差及中途遮挡，遇到误触立即失败，并保存仅含合成人体关键点的序列。它不记录真人关键点或照片。

# 合照站姿与接地投影

改动 A-20261010-68，2026-10-10。运行时 `f6e0e28`，旧版 `ea2861e`。

## 画面问题与实现

当前发行合照中的格力乔、赛罗等英雄鞋底明显朝向镜头，脚下没有接触阴影。核对代码确认，合照已使用所选战斗模型和材质，但直接采样胜利预览姿势，跳过了战斗中的脚底校正。

新增独立的合照姿势采样：保留胜利上半身，使用已有鞋底几何校准与腿部 IK 将双脚放稳。迪迦单独校准此次合照的脚底，之后恢复战斗参考值。冻结模型前完成修正，不改变网格、腿长、原色贴图或角色选择。英雄的尺寸、位置与姿势在倒数、人物取景和重拍过程中保持固定。

合照创建时，将冻结英雄的真实网格投影到照片地面方向，生成一张 512×131–147 的线性遮罩。阴影向背景月光的反方向延伸，脚底接触较深，远离地面的轮廓逐渐变淡并柔化；不是圆盘或椭圆占位图。投影按照片地面作近似，不是对背景照片重建真实三维地形。遮罩只生成一次，随合照根节点销毁，重拍不重新生成。

本轮只改善英雄站姿和接地。真人抠图边缘、人物投影与环境光融合仍需要独立验证；不能把合成人物回放当作真人照片验收。泽塔、德凯强劲型仍缺真实模型，捷德机敏形态继续按用户要求暂缓。

## 迭代与失败记录

首轮脚底测量发现迪迦还保留约 0.0272 单位的抬脚间隙，未放宽断言，补上仅用于合照的几何校准后通过。首轮投影隔离检查通过禁用渲染器作比较，出现了英雄上半身像素差异；最终保留完全相同的几何和渲染边界，只切换投影材质强度，检查地面变化和重复渲染。两次失败日志分别为 `logs/photo-grounding-geometry.log`、`logs/photo-grounding-geometry-final.log`；最终通过日志为 `logs/photo-grounding-shadow-stability.log`。旧新完整构图日志为 `logs/photo-grounding-before.log`、`logs/photo-grounding-composition.log`。

## 复现

```bash
UNITY='/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity'
"$UNITY" -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.PhotoGroundingReview.Run -quit \
  -logFile "$PWD/logs/photo-grounding-review.log"
"$UNITY" -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.PhotoGroundingReview.Composition \
  --photo-output "$PWD/artifacts/photo-grounding-new/after" \
  --photo-framing-output "$PWD/artifacts/photo-grounding-new/framing" -quit \
  -logFile "$PWD/logs/photo-grounding-composition-new.log"
bash scripts/check.sh
bash scripts/build_macos.sh --release
.venv/bin/python scripts/guided_player_check.py --hero Grigio --tempo-skills \
  --gesture-wobble --gesture-entry-noise \
  --output artifacts/photo-grounding-new/guided \
  --log logs/photo-grounding-new-guided.log
```

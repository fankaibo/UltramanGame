更新日期：2026-10-03  
基线版本：`d575b3e`（`codex/guided-arcade`，代码与验证证据基线；本地与 `origin` 一致）
参考依据：[参考街机视频拆解](参考街机视频拆解.md)、[街机画面对照与取证](街机画面对照与取证.md)、[战斗演出升级验收](战斗演出升级验收.md)、[验证记录](验证记录.md)。

> **进度口径**：本文件用于记录差距和拆解验收，不作为项目总进度的第二个来源。任务数量、权重、依赖、冲突预约和总体百分比以唯一看板 [`开发任务看板.md`](开发任务看板.md) 为准；本文件的细项估算用于解释差距，不与看板百分比相加。

这份文件把“当前能玩”与“接近商场街机成品”分开记录。百分比是排期用的加权完成度，不是画面质量评分，也不是孩子真人识别准确率。每个任务只有在写入证据路径并通过对应验收后，才可以改为“完成”。

## 当前结论

当前版本已经具备完整的家庭游戏闭环：启动、语音引导、体感变身、普攻、防御、怪兽轻度反击、大招、胜利结算、自动合照、预览、再开一局和断流恢复均已有代码和合成流程证据。`scripts/check.sh` 最近一次通过 680 项检查，发行版整局回放也已通过。

与参考街机视频相比，主要差距集中在四处：

1. 参考机台是竖屏近景，角色几乎填满画面；当前为适配电脑投屏电视的 16:9 横屏，角色和镜头距离更保守。
2. 参考机台的角色模型、材质和动作库更接近商业成品；当前只有迪迦使用高分辨率资源，捷德、格力乔、梦比优斯及部分其他英雄的贴图/网格精度不足，泽塔和德凯仍缺可用模型文件。
3. 参考机台的普通拳、怪兽前冲、受击和大招是连续镜头；当前已经有推进、冲击、拖尾、烟尘和特写，但仍有有限动作片段和待机间隔偏长的问题。
4. 参考机台的音乐、音效和角色声音是完整版权素材；当前内置音乐是原创循环，本机歌曲需通过设置导入，缺少已授权的其他英雄影视原声。

## 多任务并行、冲突与状态定义

本文件负责解释街机差距；任务数量、权重、完成百分比和当前基线只以 [`开发任务看板.md`](开发任务看板.md) 为准。并行任务领取后，必须在看板记录负责人、分支/worktree、锁定文件、依赖和验收命令；没有记录就不视为已领取。

- **并行边界**：一个任务使用一个 `codex/<task-id>-<slug>` 分支或独立 worktree，只改自己声明的目录。共享入口（`ArenaController.cs`、`RiggedActor.cs`、`HeroRoster.cs`、`HeroSelection.cs`、`PhotoComposition.cs` 和追踪文档）同一时间只允许一个任务持有编辑锁；其他任务通过新增文件、资源或交接说明提供补丁。
- **冲突处理**：合并前先更新到看板基线；只解决自己任务范围内的冲突，不覆盖另一任务的证据。合并后由集成者运行 `git diff --check`、`bash scripts/check.sh`、相关 Unity 构建和至少一次整局回放，再更新提交哈希与证据路径。
- **状态定义**：`Planned`=未开始；`In progress`=已领取且正在修改；`Blocked`=等待依赖、素材、授权或环境；`Review`=代码/资源已提交但专项验收未齐；`Done`=依赖、验收、提交和索引都齐全。状态不能跳过证据直接改为 `Done`。
- **百分比规则**：只按看板的任务权重计算总体百分比；文档、审计或重复验证本身不增加实现百分比。外部素材、真人摄像头、电视投屏或授权音频未完成时，保持对应任务的实际完成度并记录阻塞原因。

## 并行开发的冲突控制

### 可以安全并行的边界

- T01 只负责姿态协议和识别核心；T02/T03 只负责表现层；T06 只负责音频；T07 只负责合照；T08 只负责性能工具和资源生命周期。它们可以分别在独立分支工作。
- T05 的模型、材质和许可证记录尽量只新增资源文件，不同时重排 `HeroRoster.cs`；英雄数据由集成阶段一次性接入。
- T09 只提交现场日志、参数和复现说明，不把真人照片、密钥、下载缓存或临时构建产物加入 Git。

### 高冲突文件

下面文件是共享热点，同一时间只允许一个工作包修改；其他分支应通过接口需求或补丁说明交接：

- `unity/Assets/Scripts/Runtime/ArenaController.cs`：流程、输入、设置、合照和 HUD 的集成入口。
- `unity/Assets/Scripts/Runtime/RiggedActor.cs`：英雄和哥尔赞的动作、受击、特效锚点集中在此，T02/T04 不应同时直接改同一方法。
- `unity/Assets/Scripts/Core/HeroRoster.cs`：英雄选择、技能名称和资源可用性共享数据。
- `unity/Assets/Scripts/Core/Pose.cs` 与 `GestureRecognizer.cs`：T01 的独占边界。
- `docs/改动索引.md`、`docs/验证记录.md`：只由集成者在合并后更新，避免多个分支改同一表格。

### 合并规则

1. 分支名使用 `codex/arcade-<task-id>`，提交信息以任务 ID 开头，例如 `T02 improve continuous strike recovery`。
2. 合并前先从当前基线更新；只处理自己任务范围内的冲突，不覆盖其他分支的新证据。
3. 集成者按顺序运行 `git diff --check`、`bash scripts/check.sh`、开发版构建、发行版构建，再运行至少一次无键鼠完整回放。
4. 合并后在本文件更新任务状态、完成度、提交哈希和证据路径，再追加到 `docs/改动索引.md`。
5. 任一任务若依赖外部模型、音乐或 API 密钥，状态写为“待外部素材/待现场”，不能用其他角色资源代替并标记为完成。

## 每轮完成定义

一个任务只有同时满足以下条件，才从“进行中”改成“完成”：

- 源码、资源或设置变更已提交，且提交信息带任务 ID。
- 有针对该任务的自动检查或可复现人工步骤。
- 有当前版本生成的截图、录像、日志或资源审计路径。
- 没有把合成输入结果写成真人准确率，也没有把旧版本截图写成当前版本证据。
- 若依赖外部素材，记录来源、许可证、文件哈希和导入路径；缺失时保留“待导入”。

## 当前最重要的验收缺口

1. **角色素材**：补齐低清英雄和缺失的泽塔/德凯模型，否则镜头越近，画面差距越明显。
2. **连续动作**：让普通拳、怪兽冲刺、受击和起身成为连续动作段，而不是依靠单个姿势和特效连接。
3. **镜头构图**：在 16:9 电视约束下模拟参考视频的近景占屏比例，同时保留孩子动作提示和右下角预览。
4. **音频来源**：明确区分内置原创循环、用户导入歌曲和已授权角色音频，避免音乐“变了”却无法解释。
5. **真实验收**：使用真实孩子和小米电视记录动作成功率、误触率、语音理解时间和端到端反馈延迟。

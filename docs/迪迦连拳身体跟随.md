# 迪迦连拳身体跟随

A-20261018-160，基线 `e5d8698`。参考本机街机录屏 50–56 秒，玩家连续抬臂、侧倾，角色与出招组成连续动作段。录像不能证明街机内部算法；本轮针对本项目中实际发现的动作中断修复。

## 差距与修改

`LiveReadyPose` 原先只在待战时跟随躯干，远程出拳会清空身体目标；`RiggedActor` 同时在 0.10 秒内关闭身体层。实际同输入对照确认，左右交替倾斜时每次出拳都把角色重新拉直，然后在收招后再恢复侧倾。

本轮仅让迪迦在远程普攻期间继续接收肩部斜率与肩／髋相对倾斜，沿用现有幅度上限、死区和 0.14 秒平滑。预设转髋、发力、左右拳伸臂和出招快慢继续叠加；双脚仍以原支点重新求解，没有把脚与身体一起横移。

- 普攻判定、伤害、能量、投射物时钟、护盾／大招阈值均不变。
- 只使用可见肩膀和可靠髋部；半身画面失去髋部时，横向倾斜归零，保留肩部斜率。
- 防御、近战、受击、必杀仍由各自的动作接管；键盘、断流和新局继续释放身体跟随。
- 其他英雄保持原先远程躯干逻辑，后置打磨的优先级不变。

## 同输入连续验证

`RangedBodyReview.Before/After` 使用相同 9 秒输入，四次左右交替快慢远程攻击；另一个不倾斜的隐藏骨架只用于计算支撑和躯干偏移，不参与画面或玩法。15／30／60 Hz 共 945 帧玩法记录前后一致，每组 4 次命中。

| 采样 | 旧版最大相邻帧头位变化 | 新版 | 出招期间身体侧倾相对中性骨架 |
| --- | ---: | ---: | ---: |
| 15 Hz | 0.264382 | 0.139196 | 0 → 0.187809 |
| 30 Hz | 0.215176 | 0.100785 | 0 → 0.190129 |
| 60 Hz | 0.191196 | 0.097184 | 0 → 0.190620 |

单位为场景单位；这些指标只描述这一段固定输入，不能解释为整体动画质量提高相同比例。脚底相对中性骨架误差约 0.000001，最低网格约 -0.000612，零时间重复采样漂移为 0。

58 Python 测试与核心／通信累计 2324 检查通过。新增检查覆盖左右拳身体保留、出招中更新、半身遮挡、零时间、护盾接管与新局释放；既有其他英雄默认逻辑继续通过。五英雄 × 三采样率的 `RangedCastTransitions --live-body` 验证发射前后防御、意图转确认、暂停、新局及远程转近战；只有迪迦在远程动作中保留身体倾斜。

## 取证修正

初次渲染发现参考骨架入镜。先设置 `forceRenderingOff` 仍未解决，因为共用 `CharacterReview.Save` 将隐藏骨架烘焙成新的可见静态网格。现已让快照遵守这个隐藏标记，并在每次保存前断言参考骨架没有生成可见快照。旧版运行时代码重新恢复取基线，再恢复候选重出对照。错误图片不作为有效对照，关键帧及日志保留为 draft／draft2。

取证钩子另有一次 C# 局部变量重名编译失败，已修正并保留日志；未将失败包交付。

# 摄像头稳定性与自动恢复

2026-09-09。针对此前长时间游玩后识别进程退出、游戏停在等待画面的情况，增加独立进程恢复，并对原生推理做对比测试。

## 已复现的问题

旧配置为 MediaPipe 1.0.1 / Metal / SRGBA。在 Apple M3 上，以每秒 30 张新建的 640×480 黑色画面运行原生推理，不打开摄像头，约 546 秒后同样退出，退出码 134。日志仍为 `Error creating pixel buffer: -6662`，随后原生 `CHECK` 中止进程。最后一个周期记录为 540 秒、16,201 帧，进程最高驻留内存记录约 1,140.1 MiB。

这证明故障不依赖真实摄像头权限或人物是否入镜。Apple 将此错误码定义为像素缓冲区分配失败；它不能单独证明是哪一层发生了泄漏，也不能把峰值内存直接当成当前内存。由于错误在原生库中中止整个进程，Python 的 `try/except` 无法恢复该进程。

- 错误码：[Apple CoreVideo 文档](https://developer.apple.com/documentation/corevideo/kcvreturnallocationfailed)。本机 SDK 的 `CVReturn.h` 也将 `-6662` 映射为 `kCVReturnAllocationFailed`。
- 原生分配路径：[MediaPipe util.cc](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/objc/util.cc)。上游主分支可能变化，本次本机崩溃证据保存在 `logs/native-image-soak.log`。

## 恢复行为

通过 `启动游戏.command` 启动时，启动器一直持有姿态、取景预览、合照三个 IPv4 回环监听 socket。子进程通过继承的描述符使用它们；进程退出后端口仍属于本次游戏，不采用“找空端口、释放、再绑定”的方式。

每处理完一帧才推进心跳，约每秒发一次计数。启动 20 秒仍未处理首帧、运行中 6 秒没有推进、或原生进程退出，都会先结束并回收旧进程，再重建唯一的相机进程。两分钟内最多自动重启三次，间隔为 1、2、4 秒；反复失败后停止重试，终端显示原因与日志位置，游戏仍可切换键盘练习。

Unity 在画面中断时暂停这一局，保留怪兽剩余血量、普攻次数和已攒能量，取消未结算动作。新进程使用新的 `streamId`，清空旧动作历史，避免重连时把伸出的手当成一次新攻击。恢复后站稳约 1.2 秒继续，并保留引导后的反应时间。断线提示改为“相机连接中断，进度已保留”，不再把服务断线提示为人物离开画面。

关闭游戏或关闭启动终端时，先清理游戏与相机子进程，再释放监听 socket。新一次启动把上次 `camera-last.log` 保留为 `camera-previous.log`，本次重启记录连续追加；不记录摄像头视频或人物关键点。手动运行 `scripts/camera.sh` 是独立调试服务，不经过此启动器恢复流程。

## 验证

- `logs/camera-recovery-checks.log`：Python、C# 规则及回环测试，覆盖进程被杀、原生调用卡住、启动无首帧、重试上限、关闭期间不重启、三路连接恢复、端口持续持有与最终释放、旧动作清理及同局恢复。
- `logs/camera-launcher-tests.log`：临时游戏替身与实际启动器的 SIGTERM 清理测试，确认两名子进程退出、上次故障日志保留。
- `logs/camera-recovery-player-check.log`：真实编译好的 Unity 玩家应用连接合成动作，在第一拳命中后强制终止识别子进程。保留血量 49、能量 1，原游戏进程恢复到战斗并继续出拳，仅变身一次。没有打开真实摄像头。
- `logs/pose-cpu-parity.log` / `logs/pose-metal-parity.log`：MediaPipe 官方 `pose.jpg` 测试图，两种方案各 120 帧均检出人体。CPU 平均 8.47 ms，Metal 平均 4.29 ms；最后一帧 33 个关键点的二维最大差异为 0.00170，深度最大差异为 0.01862。此对比不是儿童动态动作准确率评测。
- `logs/cpu-native-pipeline.log`：官方测试图替代摄像头输入，通过实际 LatestCapture → 原生 CPU 推理 → 姿态桥 → C# 接收与预览管线。15.01 秒处理 450 帧，450 帧检出人体，平均 8.7 ms，未跳过采集帧。

官方测试图来源为 [MediaPipe 测试数据](https://storage.googleapis.com/mediapipe-assets/pose.jpg)，上游 [PoseLandmarker 测试](https://github.com/google-ai-edge/mediapipe/blob/v0.10.21/mediapipe/tasks/python/test/vision/pose_landmarker_test.py) 使用该图。图片仅保存在本机测试缓存，不加入游戏资源。

## 复现命令

```bash
# 故障、规则、回环与启动器生命周期检查；不打开摄像头
bash scripts/check.sh

# 原生推理长测：每一帧都新建原生 Image；不复用一张 Image 掩盖分配问题
MPLCONFIGDIR="$PWD/.cache/matplotlib" .venv/bin/python scripts/soak_model.py --seconds 1200

# 已构建游戏中的中途断线恢复；合成动作、后台运行、不打开摄像头
.venv/bin/python scripts/recovery_player_check.py
```

新恢复流程需要 macOS/Linux 的 POSIX 描述符继承。测试没有重新开启家庭摄像头，也没有测量小米电视投屏延迟；孩子真实动作与长时间家庭游玩的最终体验仍需下次试玩确认。

# 街机画面对照与取证（2026-09-19）

当前优先级是角色连续动作、镜头、打击反馈、场景构图和完整引导流程。帧率专项优化后置；本轮不修改动作识别门槛、血量、蓄能或儿童反应时间。

## 本轮修改

- 哥尔赞双臂的运行时方向修正原先会把肘部旋转继续传给手掌。现在保留动画中手掌的世界朝向，再调整肩肘，让手掌不会附带翻转。左右爪仍由各自攻击动画带动，主爪位置和接触时点保留。
- 保留战斗中角色的大小，调整富士山背景的垂直构图，让山顶和天空能进入战斗画面。大招特写采用相同的远景定位原则。
- 移除横穿山体的宽蓝色光带及重复的近处流星几何体，改为每 16 秒出现一次、持续约 0.85 秒的细短流星。路径位于山峰左侧的天空；喷发烟柱、熔岩弹和火星保留。
- 怪兽爪击改为一条较宽的主爪轨迹加两条更细、更短的余波，主轨迹绑定实际攻击手骨；接触环和冲击火花继续负责命中时刻，避免三条等宽线同时扫过屏幕。
- 怪兽手臂演出改为非对称姿势：攻击手前伸并抬高，另一只手回收至胸侧；蓄力、恢复和左右交替冲刺都沿用这个前后层次，减少“双手同时伸平”的僵硬轮廓。
- 格挡增加双方接触反应：英雄上身短暂后仰承力，怪兽胸部与头部反弹收爪；护盾中央更透明，接触处产生压缩和向外扩散的六边形光波。
- 迪迦左右拳在保留蒙皮手部片段和脚部落点的同时，叠加小幅转肩、胸部下沉和延迟头部跟随；左拳、右拳使用相反方向，避免只移动手臂造成木偶感。
- 能量满后的引导验证会先发送约 0.75 秒收手窗口，再保持大招姿势；这对应游戏的“先收回双手，再摆光线姿势，停一下”提示，避免持姿误触发或验证卡在能量已满状态。
- 普攻连续命中增加街机式连击提示，2.6 秒没有命中或被怪兽击中会断连；只改 HUD 表现，不改伤害、蓄能或识别门槛。
- 限制独立石块生成在近处真实地面上，消除远景投影混合区域中石块看似悬浮的问题。
- 现有双向模式按钮保留：体感左下角可切回按键，F2 在设置和合照里也生效。代码见 `ArenaController` 的 `DrawModeSwitch` 和 `Update`；此前实机切换结果见 `输入模式切换修复.md`，本轮没有把旧验证当作重新点击按钮的证据。

## 可审查的画面对照

`artifacts/strike-readability-20260919-claw/review.html`：同一段 16 秒输入、相同随机种子和渲染参数的左右对照，无声。左侧为 `3c649ed` 的当前基准，右侧为本轮修改。每侧 480 张 1280×720 图片，离线 30 fps 输出，不表示玩家帧率。

序列包含两次左拳、两次右拳、左右爪交替、一次格挡和一次受击。新版通过主手特效绑定、四个接触时刻的可见像素、待机无残留与重置清理检查；主手拖尾有效模拟帧数为左拳 44、右拳 44、右爪 47、左爪 47。左右爪在独立角色复核中分别到达护盾平面约 0.103 / 0.107 Unity 单位，主副手前后间隔约 0.586 / 0.581。

`artifacts/strike-readability-20260919-claw/after/render-source.txt` 保存 UTC、Unity 版本以及角色、场景、特效和背景着色器的 SHA-256。当前源码必须与该记录一致，才能使用这些帧证明当前效果。

## 取证纠正

之前的 `cinematic_player_check.py` 只运行玩家回放和检查日志，不会更新 `artifacts/cinematic-combat/frames`。这些帧来自独立的 Editor 渲染，因此旧帧不能证明之后的代码改动有视觉收益。历史完整流程通过记录仍有效，但不将旧帧、旧录像称为本轮画面。

现在实际玩家回放会生成独立的 UTC 目录，在游戏自身的渲染帧末截图，并核对截图文件与本次日志相符；记录程序集 SHA-256、战斗开始、左右爪、大招特写、光线、受击、暂停和胜利图。未通过截图检查时测试失败，不回退到旧图。本轮也撤回了未经新画面验证的拖尾穿透显示试验，保持正常深度遮挡。

## 仍待改善

格尔赞的源网格和贴图仍较粗糙，手掌方向修正不等于重做模型。长段攻防仍以有限动画片段编排，爪击轨迹虽已分出主次，仍有线条化倾向；角色的材质细节和动作丰富度尚未达到商场参考。合成输入验证不代替孩子真人试玩，也不能证明电视投屏延迟。

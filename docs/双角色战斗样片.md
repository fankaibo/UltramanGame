## 模型验收

哥尔赞源模型为 Source MDL v48，49 根骨骼，2591 个拆分顶点、3594 个三角面。转换时焊接 UV/材质接缝上的重复位置，留下 1889 个顶点，再做一级细分；修正了未经焊接直接细分造成的脚踝裂缝，以及屈膝时脚掌跟着小腿翻转的问题。新增 8 个 IK/膝肘控制骨，导出 6 段动作。

身体原贴图只有 **256×1024**，眼睛 **64×64**。它能用于验证怪兽动作和镜头，但不是精细现代模型；细分只改善轮廓，不能补出缺失的皮肤细节。来源与哈希记录在 `Assets/Editor/CombatSample/Characters/Golza/ATTRIBUTION.txt`，网站的上传者许可标记不等于官方商业授权。

迪迦样片使用独立 FBX，新增步行动作和较长的出拳预备/重心转移/恢复；原游戏的 8 段动作和伤害时钟未改。双方高度分别为迪迦 3.45、哥尔赞 3.60 Unity 单位。哥尔赞以骨盆下方定位，防止尾巴把模型中心推离双脚。

## 实现隔离与复现

候选素材和演出代码位于 `unity/Assets/Editor/CombatSample/`，通过 `AssetDatabase` 加载；没有放进 `Resources/Characters/Golza`，也没有写入玩家场景，正常玩家构建不引用这些候选素材。`scripts/prepare_tiga.py` 只有显式传入 `--combat-sample` 才启用新动作。

```bash
Blender --background --factory-startup --disable-autoexec \
  --python scripts/prepare_golza.py -- \
  artifacts/character-sources/golza/Golza artifacts/character-review/golza --export --review

Blender --background --factory-startup --disable-autoexec \
  --python scripts/prepare_tiga.py -- \
  'artifacts/character-sources/Ultraman Tiga.blend' artifacts/character-review/tiga-sample \
  --combat-sample --export

Unity -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.CombatSampleReview.Render -quit -logFile "$PWD/logs/combat-sample-render.log"

python3 scripts/encode_combat_sample.py
```

转换需要将官方 SourceIO 仓库解压为 `.cache/character-tools/SourceIO`；本轮使用其 5.5.5 版本，归档校验值见署名文件。复制转换后的 FBX/PNG 到上述 Editor 候选角色目录，再运行 Unity。只看少量关键帧可调用 `UltramanGame.Editor.CombatSampleReview.Keyframes`。所有步骤无需开启游戏或真实摄像头。

## 结果与后续边界

完成全长 600 帧渲染，所有导入动画均能采样，没有非法骨骼坐标；迪迦手部相邻帧最大位移 0.319 单位（检查阈值 0.65）。这证明素材和编排能运行，不等于真人试玩或最终动作品质验收。

现有项目检查通过：14 项 Python 测试及 187 项 C#/跨进程检查，共 201 项。三个转换/编码脚本通过 Python 语法检查；视频容器实测为 H.264 + AAC、600 帧、20.000 秒。

仍需改进：脚步与移动速度的严格匹配、腰肩的力量传递、怪兽爪部姿态和攻击幅度、较低分辨率皮肤、角色与平面背景的融合。样片是预先编排的演出，尚未连接到孩子的识别输入；需要先确认画面方向，再把合适的动作与效果接入实时战斗。之前发现的长时间运行摄像头 GPU 异常也不在本轮修复范围内，不能称为已解决。

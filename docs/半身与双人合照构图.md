# 半身与双人合照构图

旧合照把半身人物的肩线对齐奥特曼。摄像头只拍到胸口或腰部时，身体下沿因此悬在背景中；调暗人物无法消除这个构图问题。双人入镜时，姿态模型往往只跟踪其中一人的脸，也会使整个组合偏向一侧。

现在按实际取景安排右侧人物：

- 半身使用前景肖像构图，下沿延伸到照片边缘，按整个可见轮廓居中。双人和举手都在右侧可用范围内缩放，保留相同宽高比例。
- 全身仍按头顶到脚底的参考与英雄匹配，双脚放在原来的地面基准线上。
- 轮廓触及摄像头下沿时，不能仅凭推测出的脚踝点将其认作全身；即使姿态数据晚到，也不会沿用上一帧的全身判断。
- 五位英雄的模型、材质、位置和大小固定；取景及重拍只调整人物。界面说明半身也能拍照，退后让双脚入镜可拍全身。

这次不补造身体、不改人物身份，也没有调用 AI 或上传家庭照片。人物在镜头左右边界被截断、抠像硬边和场景光照融合仍有待解决。当前 AI 管线仍是调色参数，不是生成式融合；本轮修正不能代替这项工作。

## 验证与对照

`PhotoFramingReview` 使用相同的合成透明人像，由真实 Unity 合照相机输出修改前后画面。基线为 `0f668553c21badd8f5ba725d328ba2ea57af5298`，运行时源码摘要随输出保存。

五英雄各检查半身、双人、全身和举手；迪迦另外检查 2560×1440，共 24 组。半身人物的有效像素延伸至照片第 0 行；全身脚底维持原地面位置，人物不覆盖左侧英雄。重拍后英雄变换保持一致，背景底图仅有极少量 GPU 阴影边缘舍入差异。对照页也检查前后左半画面，避免把放大人物误变成缩小英雄。

`scripts/check.sh`：33 项 Python 测试、330 项 C# 核心检查、包含跨进程协议的 333 项检查通过，保留防御／大招姿势抖动回归覆盖。macOS 构建与本地开发签名通过。

实际最终打包版完成 140.2 秒无键鼠流程，自动保存两张 TEST 照片、重拍、倒数照片流中断恢复、预览姿势流中断恢复和举手进入下一局均通过。照片预览与保存图中心区域的颜色差 P99 为 0；95 帧防御深度波动、10 帧大招深度波动期间误触普攻为 0，成功格挡和必杀各两次。测试没有打开真人摄像头或调用 AI。

运行前后的程序摘要均为 `81d7fa7a6b19fd8fce4842689d725612c2edc3fd9471f9bba40b8c072e4c1ee0`，资源摘要均为 `804335bea41031d66d5b5fa997e068d82586891d6a5ac1d053ab551e365f3403`。前后左半画面的逐像素对照记录在 `provenance.json`；英雄变换完全一致，允许极少量 GPU 阴影边缘舍入误差，不把它当作角色缩放。

本机对照入口为 `artifacts/photo-framing/index.html`；照片、源码摘要和实际打包版流程证据均保留在忽略的验证目录，不能当作孩子真人试玩的结论。

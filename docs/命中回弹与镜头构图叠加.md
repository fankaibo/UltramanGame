# 命中回弹与镜头构图叠加（A-20261019-170）

基线 `38348a8`。复看街机录屏 50–56 秒代表段，参考游戏把身体受击、接触闪光与短促镜头反应连在一起。当前代码虽然已有命中震动，但先设置的相机偏移会被后续连击／迎击镜头覆盖。

## 具体问题与改动

旧版 60 Hz 同输入对照中，移除命中震动后，格挡和受击镜头位置仍逐帧相同，峰值差为 0；它们的专用构图确实覆盖了之前的震动。连击近景也会削弱前面的偏移。

仅迪迦普通战斗改为先完成镜头构图，再叠加有界的局部位移和轻微滚转。使用现有命中时钟，0.28 秒内收束；左右拳与来袭方向区分，仍服从原镜头移动限速。大招、入场、展示和其他英雄继续使用原路径。没有改变识别、伤害、攻速或指令时间。

不使用随机连续抖动，也没有叠加新的全屏闪白。目标是让原有闪光、音效和身体受击的同一次命中在镜头上可见，而不是用大幅晃动掩盖动作。

## 对照与验证

证据目录 `artifacts/a170-contact-camera/`。

- `ContactCameraReview.Before/After`：连击、远程、格挡、受击四段；15／30／60 Hz；每段另跑关闭命中偏移的控制组。1680 行前后战斗状态、血量、命中、动作年龄和镜头阶段一致。
- 12 组新版回弹均可测、按时归零；零时间重绘固定。60 Hz 峰值位移：格挡 0 → 0.03849、受击 0 → 0.05292 世界单位。连击与远程保留原镜头节奏，所有测试背景覆盖通过。
- `ComboCameraReview.Framing` 检查真实蒙皮：迪迦三帧率头部没有压住 HUD，双手留在画面内，最大镜头速度不超过原 13.5 单位／秒限速；其余四位可用英雄的构图检查通过。
- 同时修正构图验证工具未设置英雄配置的问题，并增加输出目录入口，避免覆盖旧验证资料。此修正不改运行时英雄资源。
- `scripts/review_contact_camera.py` 校验真实旧版源码、时序和完整帧，生成左旧／右新的 16 秒连续对照，顺序为连击、远程、格挡、受击。离线 2560×720、30 FPS，不代表实际游戏帧率。
- `bash scripts/check.sh`：58 Python 测试、累计 2363 核心／通信检查通过。

视频完整性与摘要校验后，仅清理本轮编号中间帧 160.1 MiB，每段保留 15 张关键帧；视频、原生截图、照片和轨迹继续保留。记录为 `frame-retention.json`；再次编码需重渲染完整帧。

# 迪迦源动画手型排查（A-20261012-138）

基线 `859aa87`，2026-10-12。高位出招画面中一侧手的轮廓看似张掌，先核实是否源动画缺失握拳，不直接增加一层指骨修正。

新增只读编辑器工具 `UltramanGame.Editor.TigaHandShapeReview.Inspect`。对 Idle／LeftPunch／RightPunch／Guard／Beam 各取 0%、25%、50%、75%、99.9% 五个时刻，每次独立实例化模型，避免前一动画未覆盖的通道污染。共记录 25 个样本，每个样本含 30 个左右手指骨；没有改动 FBX 或运行时。

证据为 `artifacts/tiga-hand-shape-20261012/source-hand-clips.txt` 和 `finger-rotation-comparison.json`，Unity 日志 `logs/a138-inspect-fresh.log` 确认执行完成。归一化四元数后，与 Idle 起点比较：待机／左右拳／防御各样本的指骨最大差异约 0.00043°，属于输出精度范围；Beam 中段最大差异约 71.62°，结束回到闭合手型附近。作者脚本也明确把普通动作设为闭合指骨、大招设为张掌。

结论：当前证据不支持“普通出招源动画忘了握拳”这一假设，因此没有增加冗余握拳覆盖。它仍不能证明最终蒙皮轮廓、相机角度和运行时跨动作混合正确；接下来须在真实可见运行时检查必杀前后及左右拳近景，不能把源动画检查当成完整手型修复。用户提出摄像头高位验证问题后，优先补齐 A-139 真实输入诊断；本项运行时视觉排查暂存，资料与工具已留档。

# 无键鼠引导与自动合照

2026-09-10 根据家长实际试玩反馈继续开发。本轮目标是启动后以语音和身体动作完成整局，不再要求孩子点击合照、快门、重拍或重新开始；同时扩大主要画面、补充入场与胜利演出。此前的效果升级是阶段成果，不能据此把参考街机品质称为已经完成。

## 刚才运行的问题证据

原始 `logs/game-last.log` / `logs/camera-last.log` 已复制到本机忽略目录 `artifacts/guided-arcade/reported-*.log`。

- 战斗取景正常，记录 `[Preview] displayed source=camera size=320x240`；已完成胜利。
- 家长点击合照后只有 `live viewfinder opened; waiting for explicit shutter`，没有人像显示、倒数或照片保存事件。
- 识别服务在进入合照的时间段处理速率下降，随后记录 `worker_failure reason=processed frames stopped` 并开始重启。
- 旧实现把 `PersonSegmenter.mask` 同步放在姿态/取景循环中，原生分割一旦阻塞就会连带停止心跳。上述日志与这一路径吻合，但最终根因及修复效果仍需实际摄像头并发复测，不能只凭源码下结论。

## 新流程

1. 启动即全屏，隐藏主流程鼠标和设置按钮。听引导举起双手变身；原有 50 血量、15 拳蓄能、轻度反击及语音后 3 秒反应时间保留。
2. 战斗只在底部突出当前动作：挥拳、双手护胸或光线姿势。变身加入实时螺旋光幕和缓慢运镜，怪兽使用已有步行动作入场，胜利后显示星章并转入合照。
3. 胜利语音结束并展示至少 6 秒后自动进入合照。先播放引导，再额外留 3 秒摆姿势；人像持续新鲜可见至少 1 秒后，开始完整的 5 秒语音倒数。
4. 实时镂空人像与迪迦左右分开。抠像未准备好时先显示普通实时镜头，明确标记“正在准备镂空人像”，不会让取景区域一直空白；这层备用镜头不进入照片。
5. 倒数期间任何人像过期都会取消本次拍摄，恢复后重新留准备时间并完整倒数，禁止保存旧帧或空人像。
6. 自动导出 1920×1080 PNG 到当前用户 Downloads，展示定格成片。先听完引导并放下双手，再举一只手保持 2 秒重拍，双手举高保持 1.2 秒再玩；持续举着拍照姿势不会误触发。保存失败时保留成片并自动重试。
7. 家长仍可通过 F4/F6/Esc 等键管理设置，但孩子正常流程无需这些操作。

## 故障隔离

- 摄像头仍只有一个持有者，画面只留在本机内存。
- 原生抠像移到可终止的独立进程，主循环只投递一个可覆盖的最新画面槽；等待分割结果由后台线程负责。
- 掩码与生成它的原始图片、采集时间成组返回，不能把旧掩码贴到新镜头上。摄像头忽略请求尺寸时会先等比限制在 640×480 内。
- 抠像超时或退出只重启抠像进程，保持姿态和普通预览正常运行；关闭合照释放子进程及订阅。
- 连接能在“尚无首帧”的情况下检测客户端断开，避免失效订阅留在后台。
- 日志新增订阅、抠像重启、输出尺寸和帧龄、倒数中断及手势选择事件，不记录原始人像像素。

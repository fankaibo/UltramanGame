# 姿势冲突与合照效果复核（2026-09-29）

家长反馈：防御容易被识别为攻击，大招保持过程中被普攻打断；合照的 AI 版本与原图观感差别不大。本轮修复动作优先级，并核对最近的原图、AI 输出和生成程序。

## 防御与大招

旧版防御中的单侧手腕深度变化超过肩宽的 0.25 倍，便可能被向前出拳抢占。单目姿态估计在双手遮挡或轻微活动时会出现这类变化。此外，战斗阶段双手靠近脸部时仍可能落入“举手”排除条件，无法形成护盾。

现在胸前与脸前的双手姿势优先保留为防御。只有明确的单臂前伸同时满足距离差和连续运动证据，才切换为普攻。被防御否决的出拳候选不会锁死手臂，之后真正出拳仍可触发；正常左右手出拳和收手再出拳回归通过。

大招观察到初始意图后，使用更宽的保持范围，容忍手腕深度、手高和间距抖动；最多 0.32 秒的短暂不确定或遮挡保留进度，缺失时间不计入蓄力，期间关闭出拳抢占。明确放下双手、较长遮挡、失去人体或切换识别流仍会清除状态。大招依然需要能量、收手再摆姿势与保持确认，保持同一姿势只发射一次。标准难度的保持时间没有整体下调。

修改前新增回归在“保持防御时单侧深度波动”失败，证据为 `logs/gesture-intent-before.log`。修复后，15／30／60 Hz 的防御深度波动、护脸、大招深度波动、短暂遮挡、长时间取消和重新出拳均通过。`logs/gesture-intent-checks.log` 记录 33 项 Python 测试、324 项 C# 核心检查及包含 3 项跨进程检查的 327 项集成运行通过。

## 合照核对结果

最近的原图与现有 AI 图均为 1920×1080。超过 2 个通道灰度级变化的像素占全图约 5.59%，集中在真人区域；该区域平均灰度从 108.2 降到 74.4，主要效果是调暗、调整色温。人物左侧与下方的直切边、缺失身体以及悬空构图没有被修复。

当前实现让 `gpt-5.6-terra` 返回曝光、颜色增益、羽化和包边参数，由本地 OpenCV 执行；它没有生成新的融合图像，原提示也禁止改变人物几何与构图。因此这次效果问题来自处理方式及限制，不能用“AI 调用成功”证明合成质量达标。

本地对照页为 `artifacts/photo-fusion-review/index.html`，提供原图／现有 AI 图同位置切换及像素统计；真人图片保留在被 Git 忽略的目录。使用此前授权的网关与密钥只读查询了模型列表，其中有 `gpt-image-2`；这仅说明模型被列出，尚未验证其编辑接口。本轮尚未接入或调用新的真人照片重绘。已询问用户是否允许补齐裁断处，或保持原始身体轮廓；后续按选择确定融合范围。

## 2026-09-30 边界情况复核

重新核对 Downloads 中最新的真人照片对，仍为 9 月 28 日的两张 1920×1080 图片；与上述对照页副本摘要相同。变化比例和灰度数据复算一致。视觉上主要是压暗真人，左侧／下方的直切边和悬空感仍在。之后的线性光色修正和半身构图已有独立验证，但没有把这张旧照片重新处理，也没有接入生成式修复。本次未上传真人照片或更换用户指定的模型。

进一步扩大动作抖动范围后，复现了两处此前检查没有覆盖的问题：

- 防御中单侧估计深度越过前伸阈值，会取消护盾甚至触发出拳。现在已经建立的护盾记录双手相对肩膀的位置；取消护盾并向前出拳，须同时具有画面中的实际前伸位移、单侧深度差及连续运动证据。身体平移不算伸手，收手过程中会更新参照位置，避免第二拳被旧参照挡住。
- 大招有 0.32 秒的不确定姿势容错，但另一个“松手重新准备”计时在 0.25 秒先将进度清零。现在重新准备不能提前清除未完成的蓄力；短暂不确定只暂停进度并保留对普攻的保护。持续放下双手、长时间失去姿势或失去人体仍取消，发射后仍须松手才能再来一次。

新增用例在修改前分别失败，记录于 `logs/gesture-boundary-before.log` 和 `logs/gesture-boundary-beam-before.log`。修复后 15／30／60 Hz 的左右手深度跳动、同时移动躯干、实际伸拳、短暂可见姿势偏离与恢复均通过，原有连续出拳、左右手区分和收手再出拳检查也通过。`scripts/check.sh` 完成 36 项 Python、373 项核心及包含通信的 376 项集成检查。

macOS 重新构建及本地签名完成。实际游戏回放使用更强的左右手交替深度噪声，以及超出大招保持范围约 0.29 秒的抖动；139.1 秒完成格挡 2 次、必杀 2 次，96 帧防御噪声和 15 帧大招噪声期间误触普攻为 0。自动合照 2 次、重拍、照片流／预览姿势流中断恢复与举手续局也通过。证据目录为 `artifacts/gesture-boundary/guided`，其中 `build.json` 绑定测试前后相同的程序与资源摘要。输入是合成姿势，不能代替孩子的真实摄像头体验。

## 2026-09-30 交叉手遮挡复核

补充检查发现：已建立的护盾能在手腕短暂遮挡时保留 0.20 秒，但普攻没有服从这段保护。一只手被遮挡后，双手防御几何不再成立，另一只手的深度跳动可能被当成前伸出拳，随后取消护盾。即使保持时间、深度阈值已修正，这条路径仍会误判。

现在保留护盾的同时，也阻止该时段触发普攻，并清除遮挡期间不可靠的出拳轨迹。超过容错时间仍取消防御；双手恢复后，明确前伸的左右手出拳仍然有效。本次没有降低动作保持时间或整体调整出拳难度，也没有改动大招的能量、松手重置和单次发射规则。

使用上一个提交的 `Pose.cs` 单独运行新增用例，手腕遮挡用例在修改前失败，记录于 `logs/guard-overlap-before.log`。修复后 15／30／60 Hz 的短暂遮挡、恢复、长时间遮挡与重新出拳用例均通过；全套检查为 36 项 Python、397 项核心和包含通信的 400 项集成检查，记录于 `logs/guard-overlap-checks.log`。

重新按摘要与像素核对 Downloads 照片，仍是 9 月 28 日同一对文件，变化比例仍为 5.59%。本次只做本地对比，没有重新处理、上传真人照片或更换美化模型。对照页已明确标注照片日期，避免将旧照片误认作最新程序的处理结果。

实际 macOS 打包版完成 139.1 秒无键鼠流程：94 帧防御深度噪声中包含 42 帧对侧手腕遮挡，另有 15 帧大招姿势噪声；受保护期间普攻误触为 0，格挡和必杀各成功 2 次。自动合照 2 次、重拍、倒计时照片流中断恢复、预览姿势流中断恢复和举手续局均通过，导出照片与预览中央区域像素一致。`artifacts/guard-overlap/guided` 保存结果及当前安装包的前后摘要；测试使用合成姿势和人物像素，不代表孩子的真实摄像头体验已验证。

## 2026-09-30 姿势起始阶段

继续核对“刚摆好动作”时的判定，复现了两条已有保持阶段检查没有覆盖的路径：

- 防御参照位置原先在护盾生效后才记录。如果进入姿势时一侧手腕深度已偏前，防御计时便一直无法建立。现在在胸前双手形状出现时先记录参照，再计算持续时间；之后须有明确的单侧伸手才转为出拳。已接受的拳头仍需收回，不能因为重新记录参照而变成护盾。
- L 形大招原先累计满 0.10 秒后才容忍深度波动。在第一段进度内出现持续深度偏差，会丢失这项保护并最终取消蓄力。现在首次有效识别后即启用深度容错；早期手部二维形状仍使用严格范围，持续时间、能量和松手重置条件不变。

新增用例在修改前分别失败，见 `logs/gesture-acquisition-before.log` 和 `logs/gesture-acquisition-beam-before.log`。修复后的 15／30／60 Hz 回归包括：左右手初始深度偏差、从防御真实出拳、伸拳不能自动变成护盾、收手恢复防御、刚开始蓄力就出现深度抖动，以及取消 L 形后回到防御。全套检查通过 36 项 Python 测试、424 项核心检查和含通信的 427 项集成检查。macOS 构建和本地签名通过。

第一轮实际打包回放仍捕捉到 3 次进入姿势时的向前出拳，保留于 `artifacts/gesture-acquisition/guided` 与对应日志。这表明只检查“平滑坐标已经呈现完整姿势”不够：原始相机帧已经是 L 形或防御时，平滑坐标可能还在上一动作。

进一步修正后，完整的原始双手姿势也可以优先建立动作意图；大招原始入口仍须满足严格形状和深度条件，防御使用肩膀相对位置作为参照，实际出拳轨迹继续平滑和连续确认。新增“从双手放下到 L 形，紧接着出现深度偏差”的回归在修正前失败（`logs/gesture-transition-before.log`），修正后 15／30／60 Hz 均通过，放下双手取消、左右出拳、收手再打和既有遮挡回归也通过。最终检查为 36 项 Python、427 项核心和含通信的 430 项集成检查，见 `logs/gesture-transition-checks.log`；已重新构建并签名。

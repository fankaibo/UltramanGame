# M0 实现说明

## 数据链路

Python 独占前置摄像头，MediaPipe Lite 在本机提取姿态。Unity 通过 `127.0.0.1:8765` 获取 UTF-8 JSON 行。初稿中的 WebSocket 调整为 TCP JSON 行，双方均使用标准库即可建立连接，减少原型依赖。

本机固定使用 MediaPipe 1.0.1。Apple M3 上实测默认 CPU 路径在初始化时崩溃；显式 Metal GPU 加 SRGBA 四通道输入通过真实模型测试。`vision/model.py` 统一相机与测试的模型配置，macOS 使用这条已验证路径。其他平台暂用 CPU/RGB，尚未进行原生推理实测。

相机采集采用 640×480、请求 30 FPS；这是采集请求，不是实测性能承诺。相机线程连续采集，仅保留最新一帧；推理使用 VIDEO 模式，在处理完上一帧后取最新帧，跳过已过时的中间帧，避免积压。Unity 渲染独立运行。采集线程退出时释放相机。

每条消息包含 `schema=1`、来源 `source`（`camera` 或 `synthetic`）、随机会话标记 `streamId`、递增 `sequence`、采集后的 Unix 毫秒时间 `capturedMs`、`tracked` 和 33 个 `{x,y,z,visibility}` 点。`x,y` 是原始未镜像画面的归一化坐标，模型输出的 `z` 不用于当前招式判定。Unity 会将合成输入明确标为“合成动作测试”。

预览镜像与角色映射在显示层处理。姿态消息不携带图像、音频或玩家身份，服务不保存姿态历史。服务只保留最新消息，慢连接超时退出；客户端单行限制 32 KiB，重连间隔约 1 秒，游戏在主线程读取最新消息。

接收方拒绝不支持的协议、错误点数、NaN/Infinity、超过 350 ms 的帧或明显来自未来的帧。人体存在以双肩在画面内的位置和可见性判断（最低 0.45），不以肩距过小判定人物离开，招式使用对应关节更严格的可见性门槛（0.55）。时间戳是采集返回后的时刻，不代表传感器曝光时刻，因此仍须测量动作到电视反馈的整体延迟。

## 游戏内取景预览

Python 在取得姿态后，用同一帧的副本缩小、标记关节点、镜像并编码 JPEG，限制在 320×240 内、目标约 15 FPS，不额外打开摄像头。关节最低 0.55 为绿点，不可靠但仍在画面内的预测点为橙点；可靠的双臂用线连接。橙点的位置仅是预测，不表示动作已经识别成功。画面状态使用与游戏一致的双肩 0.45、全臂 0.55 门槛。

预览通过独立的本机 TCP 连接发送，默认 `127.0.0.1:8766`；姿态连接仍只传关键点。每帧是 18 字节大端头部（`UGP1`、int64 采集时间、uint32 JPEG 字节数、uint8 来源 0/1、uint8 质量 0/1/2）及 JPEG。质量分别表示双肩未可靠入镜、人在但手臂不完整、双臂完整。单张 JPEG 上限 128 KiB，接收方在解码前核对格式、长度与图像尺寸。

两路服务分别只保留最新消息，网络发送在各自线程执行。预览缩放编码在姿态发布后执行；Unity 后台接收 JPEG，主线程更新纹理。超过 750 ms 未更新即释放旧图，显示断流提示，避免定格误导。预览的时间缓冲不参与动作判定。`F3` 或“收起”隐藏画面、释放显示纹理，不停止摄像头或动作识别；键盘模式不显示预览。

日常启动器默认启用游戏内预览；手动运行识别服务需加 `--game-preview`。`--no-preview` 只关闭独立 OpenCV 窗口。`--demo --game-preview` 使用生成的骨架测试图，画面明确标记为合成测试，不打开摄像头。图片与关键点均仅经过本机内存和回环连接，不上传、不保存。

## 动作与状态

- 前 0.25 秒用于稳定上半身输入；帧间中断超过 250 ms 时重新稳定。手肘或手腕短暂不可靠不会重启整个人体的稳定计时。
- 手臂长度判定以肩宽归一化。相机严重侧拍、身体遮挡和儿童比例仍须实测调参。
- 挥拳需要先收手，再达到伸展条件；允许手臂略弯，伸展与收回使用分开的阈值，姿势保持不会连发。拳动画为 0.38 秒，0.12 秒结算命中；回收阶段最后约 0.18 秒收到的新挥拳可短暂缓冲，暂停或丢失追踪会清空。
- 防御姿势保持约 0.08 秒生效；光线姿势保持约 0.30 秒触发；双手举高约 0.45 秒触发变身。
- 变身、光线、防御形状优先于挥拳，以减少交叉姿势误触。
- 变身需要肩部和双手腕可靠；挥拳按每只手单独判断，另一侧手肘遮挡不会禁用可见侧。防御和光线需要双臂可靠。遮挡不触发新招式，不保留过时的防御；已经释放过的光线也不会因短暂遮挡而重新释放。
- 当前仅追踪一个主要人物，不提供可靠的身份锁定。原型试玩时先避免多人同时入镜。

`Battle` 状态机与 Unity 解耦，可以在 .NET 下测试。基本状态为等待、变身、战斗、暂停和胜利。怪兽依次休息、蓄力预警、攻击结算、恢复。`PlayerPresence` 允许距最后可信上半身采集时间 600 ms 的短暂间断；旧帧不能延长这个期限。确认身体丢失或断流后自动暂停并取消未命中攻击，上半身重新稳定 1.2 秒后恢复。家长手动暂停时必须先点击继续。

当前可调默认值：怪兽生命 24，普通攻击 1，能量上限 6，光线伤害 9。每次普通攻击或成功防御增加 1 能量。怪兽休息 4 秒，预警 2.4 秒，恢复 2 秒。未防御受击只触发恢复效果，不设玩家死亡；普通攻击也能结束战斗。

`AnimatedActor` 使用两套 4×2 动作图集，根据 `Battle` 的状态选择准备、出拳、护盾、光线、受击、变身和胜利姿势，并叠加呼吸、前冲和回收。摄像头输入仍决定动作事件；这一版按用户选择优先角色相似度，取消逐关节身体跟随。`CharacterSprite.shader` 在运行时移除图集的纯绿色底色，原始素材不伪装成带 alpha 的透明 PNG。图集禁用 mipmap、压缩和非二次幂缩放，避免串帧与边缘污染。

站位采用 X、Z 分量相等的 45° 对角线：迪迦 `(-1.65,0,-1.35)`，哥尔赞 `(1.65,0,1.95)`。镜头位于迪迦后方较高处，使用 `TigaRear45Actions` 的背侧图集和哥尔赞现有正面图集。每名角色根据对手位置求前进方向，攻击前冲、受击后退和退场共用该方向；光线和护盾也按这条战斗轴定位。角色有效像素写入深度，防止更远处的地台光环穿过人物。提示字幕移至怪兽下方，蓄力和命中提示移至左侧空位，胜利卡片收窄，给两人的头部、手臂和脚部留出空间。

`GameWorld` 渲染生成的城市背景、3D 训练台、变身光圈、护盾、光线和有限数量的命中粒子。`HudPainter` 显示动作图示、能量、预警、变身/光线进度与家长设置。`GameAudio` 管理音乐交叉淡入淡出、语音优先级、过期台词清理和音量设置。`LocalMusic` 通过本机 NSOpenPanel 选择文件，异步解码后替换音乐；在准备、战斗和胜利之间保持同一首导入歌曲连续循环。只在成功读取后记住路径，失败不覆盖现有歌曲。资源来源与边界见《美术与音频说明》。

## 测试边界

`tests/CoreChecks` 编译实际使用的 Core C# 文件，检查动作重置、持续姿势、左右拳、防御、光线、暂停恢复和胜利规则。通信集成检查启动真实 Python 服务，再由实际 C# TCP 客户端读取并校验。

自动检查不能替代 Unity 编译、画面验证、真实儿童动作测试和电视延迟测试。界面与呈现代码的验证进度见《验证记录》。

## 本机启动与关闭

`启动游戏.command` 调用 Python 启动器，使用本机构建的 `TigaTraining.app`。启动器只管理自己创建的游戏与相机进程；姿态与预览服务由系统自动分配空闲端口，启动器读取就绪消息后把端口传给游戏，不占用或终止其他应用的服务。正常退出游戏或中断启动器时，先优雅停止本次子进程，超时后结束它们。独立相机窗口默认关闭，游戏内右下角预览默认开启。

游戏使用 Resources 内置的 Noto Sans SC 字体，避免 Unity 6000.6 的 macOS 系统字体加载问题。程序材质有对应的 Resources 模板，确保构建时包含 Standard shader。项目保存了 Unity 自动生成的设置和依赖锁，构建入口可由菜单或 `scripts/build_macos.sh` 调用。

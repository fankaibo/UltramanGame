# M0 实现说明

## 数据链路

Python 独占前置摄像头，MediaPipe Lite 在本机提取姿态。Unity 通过 `127.0.0.1:8765` 获取 UTF-8 JSON 行。初稿中的 WebSocket 调整为 TCP JSON 行，双方均使用标准库即可建立连接，减少原型依赖。

本机固定使用 MediaPipe 1.0.1。Apple M3 上实测默认 CPU 路径在初始化时崩溃；显式 Metal GPU 加 SRGBA 四通道输入通过真实模型测试。`vision/model.py` 统一相机与测试的模型配置，macOS 使用这条已验证路径。其他平台暂用 CPU/RGB，尚未进行原生推理实测。

相机采集采用 640×480、请求 30 FPS；这是采集请求，不是实测性能承诺。相机线程连续采集，仅保留最新一帧；推理使用 VIDEO 模式，在处理完上一帧后取最新帧，跳过已过时的中间帧，避免积压。Unity 渲染独立运行。采集线程退出时释放相机。

每条消息包含 `schema=1`、来源 `source`（`camera` 或 `synthetic`）、随机会话标记 `streamId`、递增 `sequence`、采集后的 Unix 毫秒时间 `capturedMs`、`tracked` 和 33 个 `{x,y,z,visibility}` 点。`x,y` 是原始未镜像画面的归一化坐标。Unity 同时平滑 `x,y,z`，用手腕相对本侧肩膀的深度变化判断前推；协议版本不变。`z` 是单摄像头模型的估计值，不是深度相机的实测距离，含义见 [MediaPipe 官方说明](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose.md)。Unity 会将合成输入明确标为“合成动作测试”。

预览镜像与角色映射在显示层处理。姿态消息不携带图像、音频或玩家身份，服务不保存姿态历史。服务只保留最新消息，慢连接超时退出；客户端单行限制 32 KiB，重连间隔约 1 秒，游戏在主线程读取最新消息。连续挥拳判断在 Unity 内存中为每只手保留最多 24 个相对位置，只使用最近 650 ms，不记录到磁盘。

接收方拒绝不支持的协议、错误点数、NaN/Infinity、超过 350 ms 的帧或明显来自未来的帧。人体存在以双肩在画面内的位置和可见性判断（最低 0.45），不以肩距过小判定人物离开，招式使用对应关节更严格的可见性门槛（0.55）。时间戳是采集返回后的时刻，不代表传感器曝光时刻，因此仍须测量动作到电视反馈的整体延迟。

## 游戏内取景预览

Python 在取得姿态后，用同一帧的副本缩小、标记关节点、镜像并编码 JPEG，限制在 320×240 内、目标约 15 FPS，不额外打开摄像头。关节最低 0.55 为绿点，不可靠但仍在画面内的预测点为橙点；可靠的双臂用线连接。橙点的位置仅是预测，不表示动作已经识别成功。画面状态使用与游戏一致的双肩 0.45、全臂 0.55 门槛。

预览通过独立的本机 TCP 连接发送，默认 `127.0.0.1:8766`；姿态连接仍只传关键点。每帧是 18 字节大端头部（`UGP1`、int64 采集时间、uint32 JPEG 字节数、uint8 来源 0/1、uint8 质量 0/1/2）及 JPEG。质量分别表示双肩未可靠入镜、人在但手臂不完整、双臂完整。单张 JPEG 上限 128 KiB，接收方在解码前核对格式、长度与图像尺寸。

两路服务分别只保留最新消息，网络发送在各自线程执行。预览缩放编码在姿态发布后执行；Unity 后台接收 JPEG，主线程更新纹理。超过 750 ms 未更新即释放旧图，显示断流提示，避免定格误导。预览的时间缓冲不参与动作判定。`F3` 或“收起”隐藏画面、释放显示纹理，不停止摄像头或动作识别；键盘模式不显示预览。

日常启动器默认启用游戏内预览；手动运行识别服务需加 `--game-preview`。`--no-preview` 只关闭独立 OpenCV 窗口。`--demo --game-preview` 使用生成的骨架测试图，画面明确标记为合成测试，不打开摄像头；每 16 秒轮换侧前出拳/L 形与肘部遮挡的前推拳/双手前推，覆盖深度数据的完整通信链路。普通取景图片与关键点均仅经过本机内存和回环连接，不上传、不保存；主动合照的单张输出见下节。取景窗口会短暂显示“已识别：向前挥拳 / 侧前挥拳 / 必杀光线”，帮助区分关键点显示和动作事件。

## 动作与状态

- 前 0.25 秒用于稳定上半身输入；帧间中断超过 250 ms 时重新稳定。手肘或手腕短暂不可靠不会重启整个人体的稳定计时。
- 肩部三维估计距离用于归一化相对移动，避免依赖固定像素距离；尚未训练个性化模型或完成儿童比例校准。
- `PunchMotion` 在 60–650 ms 的短时间窗口比较手腕相对肩膀的前后/向外移动，要求至少两个新观测支持。前推允许手肘被遮挡，侧前出拳不再要求固定肘角；纯上下移动、小幅抖动和整个人向镜头移动不能当作挥拳。触发后需明确回收，保持伸手不会重复出拳。拳动画仍为 0.38 秒，0.12 秒结算命中，回收阶段允许短暂缓冲下一拳。
- 防御保持约 0.08 秒；光线接受宽松的“一只手抬高、另一只横在胸前”，也接受肩宽分开的双手前推，保持约 0.35 秒。光线最多容忍 120 ms 的短暂不可靠观测，间断时不增加进度、不发射；明确放松至少 180 ms 才重新准备。变身仍为双手举高约 0.45 秒。
- 光线只在战斗阶段且能量满时启用，变身只在等待阶段启用。深度上已伸出的单拳与 L 形分开判断；从胸前防御姿势直接前推单拳可以攻击，避免二维投影将拳头误认作护盾。双手并拢护胸也不会误触双手前推必杀技。
- 变身、防御和光线以可靠肩部及双手腕为必要条件，不要求双肘始终清楚。挥拳按手独立判断，腕部不可靠时清空本手运动历史；重新看到已伸出的手不会补发攻击。已经释放的光线不会因短暂遮挡重新发射。
- 当前仅追踪一个主要人物，不提供可靠的身份锁定。原型试玩时先避免多人同时入镜。

`Battle` 状态机与 Unity 解耦，可以在 .NET 下测试。基本状态为等待、变身、战斗、暂停和胜利。怪兽依次休息、蓄力预警、前冲攻击、恢复。`PlayerPresence` 允许距最后可信上半身采集时间 600 ms 的短暂间断；旧帧不能延长这个期限。确认身体丢失或断流后自动暂停并取消未命中攻击，上半身重新稳定 1.2 秒后恢复。家长手动暂停时必须先点击继续。

怪兽血量可在“游戏设置 → 战斗”中按可承受普攻次数调整，范围 10–200、步长 10，默认 50；点击应用后重开一局，以 PlayerPrefs 保存，下次启动及重新开始均沿用。Battle 的血量上限随本局配置创建，血条使用本局上限。普通攻击伤害 1，能量上限 15，光线伤害 9。只有普通攻击命中增加 1 能量，成功防御不增加；未到命中时刻的攻击不计数。怪兽休息 4 秒、预警 2.4 秒；前冲攻击共 1.05 秒，在开始后 0.4 秒接触时结算一次护盾或受击，然后恢复 2 秒。前冲途中仍可举起护盾，暂停或释放光线会取消尚未命中的攻击。未防御受击只触发恢复效果，不设玩家死亡；普通攻击也能结束战斗。

`AnimatedActor` 使用两套 4×2 动作图集，根据 `Battle` 的状态选择准备、出拳、护盾、光线、受击、变身和胜利姿势，并叠加呼吸、前冲和回收。摄像头输入仍决定动作事件；这一版按用户选择优先角色相似度，取消逐关节身体跟随。`CharacterSprite.shader` 在运行时移除图集的纯绿色底色，原始素材不伪装成带 alpha 的透明 PNG。图集禁用 mipmap、压缩和非二次幂缩放，避免串帧与边缘污染。

站位采用 X、Z 分量相等的 45° 对角线：迪迦 `(-1.65,0,-1.35)`，哥尔赞 `(1.65,0,1.95)`。镜头位于迪迦后方较高处，使用 `TigaRear45Actions` 的背侧图集和哥尔赞现有正面图集。每名角色根据对手位置求前进方向，攻击前冲、受击后退和退场共用该方向；光线和护盾也按这条战斗轴定位。角色有效像素写入深度，防止更远处的特效穿过人物。变身完成后视野角从 35° 平滑收至 27°（光线时 26°），角色在相同视口中约放大 31%。战斗顶部栏从 103 缩至 62，动作卡片从 298×110 缩至 212×57 并下移至底部，标题字体从 29 缩至 18，动作标题从 23 缩至 15。战斗字幕位于上方空位，预警和命中提示位于左侧；实时取景从 260×253 缩至 204×195。暂停和胜利继续使用紧凑布局，重新开始则恢复变身引导。以上尺寸均为 1280×720 HUD 坐标。

怪兽攻击姿势、位移和 `MonsterAttackEffects` 共用 `Battle.EnemyAge`：蓄力先后倾，0.4 秒内向迪迦前进 2.25 个场景单位，短暂停留挥爪，再平滑退回。蓄力光圈、冲刺拖尾、三道爪痕及接触光圈按同一时序显示；格挡为蓝色，受击为橙色。没有延迟回调在暂停后补发命中。

`GameWorld` 渲染生成的城市背景、变身光圈、护盾、光线和有限数量的命中粒子。深色圆盘、外围装饰灯与常驻脚下光环已移除；背景按原比例放大并以底边对齐，让画面内的广场承接角色脚部。`HudPainter` 显示动作图示、能量、预警、变身/光线进度与家长设置。`GameAudio` 管理音乐交叉淡入淡出、语音优先级、过期台词清理和音量设置。固定中文提示默认来自随源码保存的「热血青年英雄」合成语音包，构建时离线校验并转换；游戏不运行语音模型。大招优先播放本机可选的 `Voice/beam_original` 短战吼；缺少录音时使用生成的引导。大招战吼不可被普通提示或致胜语音截断，胜利语音与庆祝音效等战吼结束才播放；暂停、静音、重开仍立即停止并清理。大招名称在特写期间显示，并在退镜后继续保留约 2 秒，在致胜画面中也能看见。`LocalMusic` 通过本机 NSOpenPanel 选择文件，异步解码后替换音乐；在准备、战斗和胜利之间保持同一首导入歌曲连续循环。只在成功读取后记住路径，失败不覆盖现有歌曲。资源来源与边界见《美术与音频说明》。

大招使用独立的 `BeamCloseup` 呈现计时：触发后 0.98 秒内把 `Battle.Tick` 的时间增量设为 0，仍传入每帧追踪和暂停状态；镜头以 0.16 秒拉近、0.24 秒退回，特写峰值视野角为 14°，聚焦迪迦上半身与 L 形手势。普通 HUD 暂时隐藏，怪兽随镜头焦点淡出，场内动作保持不变。`GameWorld.BeamStarted` 在退镜后光线首次可见时触发一次音效，伤害继续由原有 Battle 规则结算。暂停、重新开始、设置和角色展示会清理特写，不会把游戏留在冻结计时或放大镜头中。

## 测试边界

`tests/CoreChecks` 编译实际使用的 Core C# 文件，检查动作重置、持续姿势、左右拳、防御、光线、暂停恢复和胜利规则。通信集成检查启动真实 Python 服务，再由实际 C# TCP 客户端读取并校验。

自动检查不能替代 Unity 编译、画面验证、真实儿童动作测试和电视延迟测试。界面与呈现代码的验证进度见《验证记录》。

## 本机启动与关闭

`启动游戏.command` 调用 Python 启动器，使用本机构建的 `TigaTraining.app`。启动器只管理自己创建的游戏与相机进程；姿态与预览服务由系统自动分配空闲端口，启动器读取就绪消息后把端口传给游戏，不占用或终止其他应用的服务。正常退出游戏或中断启动器时，先优雅停止本次子进程，超时后结束它们。独立相机窗口默认关闭，游戏内右下角预览默认开启。

游戏使用 Resources 内置的 Noto Sans SC 字体，避免 Unity 6000.6 的 macOS 系统字体加载问题。程序材质有对应的 Resources 模板，确保构建时包含 Standard shader。项目保存了 Unity 自动生成的设置和依赖锁，构建入口可由菜单或 `scripts/build_macos.sh` 调用。

动作示意图在统一的 1280×720 HUD 坐标内连接关节点，再应用屏幕缩放矩阵。线段旋转使用局部矩阵相乘，避免 Retina 或非等比窗口缩放导致连线偏离关节。

## 胜利合照

胜利卡片的相机按钮或 F7 打开合照画面并开始 5 秒倒计时；此时游戏热键与战斗输入暂停处理，Esc 取消且不保存。倒计时使用单调时钟，每次开始最多触发一次快门。快门前检查图像时间戳（最多 750 ms，未来容忍 50 ms）和人像有效像素；没有新的人像时只提示重拍，不等待后台恢复后偷偷补拍。

合照使用 `vision/photo.py` 的第三条独立回环流（默认 8767），不复用 320×240 的关节点 JPEG。只有合照界面订阅时才处理原始摄像头帧，约 8 FPS 上限；macOS 原生 `VNGeneratePersonSegmentationRequest` 提供人像透明度，Python 清除完全透明区域的 RGB、镜像、编码 640×480 RGBA PNG。接口及遮罩语义见 [Apple 文档](https://developer.apple.com/documentation/vision/vngeneratepersonsegmentationrequest)。`native/PersonCutout.mm` 不打开第二个相机、不读写文件、不联网；通过 ctypes 从 Python 调用。关闭合照连接后释放分割请求，普通战斗不运行额外抠图。MediaPipe 的姿态设置保持原样。

传输为 18 字节头（`UGF1`、int64 采集毫秒、uint32 字节数、uint8 synthetic、uint8 present）及 PNG；两端限制 2 MiB，Unity 在纹理解码前限制 640×480、8-bit RGBA。仅保留最新帧。分割失败返回空人像并限频重试，不中断普通姿态服务。

`PhotoComposition` 使用独立离屏相机与 1920×1080 RenderTexture，把迪迦正面胜利姿势置于左半边，透明人像置于右半边。分别按有效像素边界等比缩放、底部对齐，保留中间间隔；摄像头原背景和关节点不进入照片。角色取自已有正面图集 `TigaPhotoActions.png` 的第 8 格，原有战斗继续使用背侧图集。宽高不同的游戏窗口对合照界面等比留边。保存内容仅为合成场景，不包含倒计时、提示、按钮或开发版 HUD。

`PhotoFiles` 定位当前用户的 Downloads，先写临时文件，再原子移动为唯一命名的 PNG；重拍不覆盖，失败清理临时文件并显示错误。合照只在本机保存，不上传仓库或外部服务。退出合照释放画面纹理与连接，拍摄完成后预览冻结。合成试玩使用卡通 TEST 人物，文件名带“合成测试”前缀。纯 `--keyboard` 启动禁用合照，正常相机启动后切到键盘练习仍可使用原有相机合照。

# 全身合照人物接地投影（A-20261019-166）

基线 `b5daa82`。迪迦已使用固定合照姿势、固定比例和脚下投影，人物抠像却缺少地面投影，完整入镜时容易显得浮在背景前。此次给确认全身的人物增加与月光方向一致的投影，不改变迪迦或人物缩放算法。

## 实现

- 复用当前人物 RGBA 的透明度，将轮廓投射到右侧地面；脚边较实，离脚越远越淡、越软。投射方向和地面透视压缩与迪迦已有投影一致。
- 阴影跟随已经稳定后的同一人物变换，脚下位置按可见轮廓而非透明留边计算。没有增加一套独立缩放或追踪逻辑。
- 只有 `PhotoComposition.FullBody` 确认全身时启用。半身、举手但脚部未入镜、失去人物时不显示假脚影。
- 投影是人物对象的子对象，隐藏人物与导出干净背景时一起隐藏；`PersonMatte` 继续只包含原人物透明度，不把投影当成人体发送给后续合成。
- 一次创建材质和四边形，使用现有纹理；无新增逐帧烘焙纹理。释放路径包括正常关闭、先销毁相机及先销毁整个合照场景。

## 验证与取舍

证据目录：`artifacts/a166-photo-person-ground/`。

`before`／`after` 是同一构图工具导出的 1080P／2K 迪迦合照；`PhotoFramingReview.After` 共 24 种英雄／尺寸／半身／全身／多人／举手组合通过，英雄位置、旋转与大小固定。

`PhotoPersonShadowReview` 最终结果在 `shadow-verified`：

- 1080P 全身投影影响 4208 个地面像素，2K 影响 7508 个；迪迦半幅和上方区域新增阴影像素均为 0。
- 半身和未露脚的举手照片投影像素为 0。开启／关闭投影时，人物蒙版完全一致；同状态重复渲染最大差 0–2 个色阶。
- 隐藏人物、干净背景导出、重拍、固定英雄及资源释放检查通过。
- 首轮测试直接关闭渲染器导致 Unity 重新适配方向光阴影图，造成迪迦表面少量像素变化；改用保持相同几何的材质强度开关进行隔离。另一次干净背景对照缺少与既有工具一致的预热，补齐预热后通过，未放宽越界阈值。失败日志和诊断图保留。
- 一次 Unity 检查失败退出时附带 Mono 原生崩溃信息；最终正常退出检查通过，未把失败记录算作通过。
- 58 Python 测试及累计 2324 核心／通信检查通过。源码 Release 构建与签名通过。
- 实际新包 164.4 秒高位整局通过：2071 个普通战斗帧无低手位、32 次光弹命中、两次全身合照、重拍、断流恢复和进入下一局。预览／保存 P99 差为 0；全程无键鼠、无手势选角。
- 重拍两张最终照片左半幅最大差 19、平均差 0.000197、超过 3 色阶的像素 21 个，属于待保留观察的微小渲染差异，不能宣称逐像素完全一致；离线英雄位置／旋转／比例不变。
- 签名与源码／程序集／资源哈希核对后整包更新默认游戏，上一包保留为 `TigaTraining-pre-a166.app`。

新增 `scripts/guided_player_check.py --photo-full-body` 使用有 TEST 标识的透明全身图和可见膝踝关键点；只作用于合成验证，不改变真实摄像头生产逻辑。新包会在首次显示人物的诊断日志中记录 `fullBody`，验证必须确认两次照片均走到全身路径。

复现：Unity 执行 `PhotoFramingReview.Before/After --photo-framing-output <目录>`；投影隔离与资源生命周期执行 `PhotoPersonShadowReview.Run --person-shadow-output <目录>`。

## 边界

当前验证使用明确标识的合成人物，证明构图、遮挡、隐藏与保存流程；不能据此宣称真人头发、服装边缘或照片 AI 美化已经验收。原先临时附件路径中的孩子照片当前不存在，本轮未使用私人照片或上传图片。真实儿童／小米电视、最终照片融合与整体街机画面仍待验收，总体保持 70.2%。

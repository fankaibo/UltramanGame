# 远程光弹与体感攻速（A-20261008-50）

代码提交：`8351d16`，分支 `codex/guided-arcade`。

用户指出：参考街机的普通技能有远程表现，人物出手快慢也会改变角色动作节奏；旧版本只有固定时长的近战。此次补齐从手腕速度、左右手判定，到骨骼动作、光弹飞行、命中的完整链路。

## 体验变化

- 向前挥拳发射普通光弹，侧向挥拳保留近战。仍需先收手，再主动伸出；举手、静态持姿不会持续发弹。
- 使用肩宽归一化的手腕近期位移和消息采集时间估计速度；每次有效出手生成 0.65–1.70 倍的动作速度。慢挥慢出招，快挥快出招，下一只手的缓存保留自己的速度。
- 光弹在自己的出手侧离手飞向怪兽胸前，收手后继续飞行；此时可以立即转入防御。尚未发射时取消攻击不扣血，暂停和新一局清除未命中的光弹。
- 远程攻击使用原地发射姿势，减少冲向怪兽和拉长手臂；普通光弹采用各英雄已有的主题色及独立合成发射／命中音效，不冒充影视招式原声。
- 命中一次仍扣一次普攻血量、加一点能量；默认 50 次血量、15 次普攻蓄满大招不变。怪兽预警、语音后 3 秒准备时间、防御和大招持姿时间不随攻速缩短。
- 键盘练习 `A / D` 为左右近战，`Q / E` 为左右光弹；键盘采用正常速度。体感底部提示新增“向前挥拳发光弹 · 快慢跟随你”。

这里按每次已识别挥拳的速度调整动画，不是逐帧复制真人每个关节。单目相机的深度来自姿态模型估算，摄像头角度、遮挡及儿童手臂幅度仍需实际试玩校准。

## 参考依据与边界

重新查看根目录录屏的约 50–56 秒和 90–96 秒：能看到近身动作以及横跨双方的发光技能轨迹。这支持把普通攻击补为近战与远程两类；仅凭该视频无法证明街机内部的速度识别算法。本轮实现自己的有界速度映射，没有声称复刻其程序。

## 验证

- `bash scripts/check.sh`：41 项 Python 测试、765 项 C# 规则／姿态／通信检查通过。覆盖 15/30/60 Hz、左右前冲、快慢速度、单次扣血、独立飞行、防御取消、暂停、缓存速度与最后一击胜利；包含前冲后转紧凑护盾时另一只手的初始深度噪声。
- 同路径的 `.65s / .14s` 合成前冲分别产生约 `.86 / 1.56–1.70` 倍速度；这些是轨迹驱动识别器的结果，与下面模型极限速度审查区分。
- `AttackTempoReview.Render`：五位实际骨骼英雄各用 `.65 / 1.70` 倍速度检查。每组恰好一次发射、一次命中；命中在 `.4667 / .1833s`，动作恢复在 `.65 / .25s`；发射手至目标距离约 `1.38–2.06` Unity 单位，模型最低点没有明显穿地。
- Release 1080P 近战回放 `--linked`：81.87 秒，32 次普攻、2 次大招、格挡、受击和暂停恢复通过。两段短采样为 50.0/51.5 FPS，不作为稳定帧率承诺。
- 新增 `guided_player_check.py --tempo-skills`：向真实发行版姿态接收器发送交替左右、快慢前冲，再验证防御／大招、合照／重拍／续局；最终 228 秒回放通过：44 次被接收的攻击指令中，32 次在发射前未被转姿取消并发出光弹（左右各 16 次）；快慢速度中位数分别为 1.70 / 0.866 倍；格挡 5、大招 2、持姿误出拳 0、初始偏差防御在 700 ms 内取得控制 5 次。两次自动合照、重拍、断流恢复、重新选角和下一局战斗通过，键鼠事件 0、照片预览 p99 误差 0。

本机证据位于 `artifacts/attack-tempo-20261008/`：`validation.txt`、五位英雄 `sequence.csv`／`flight.png`、迪迦快慢序列、`render-source.txt`；发行版回放使用合成姿态和 TEST 照片，不调用真人相机。`encode_attack_tempo_review.py` 校验源码哈希和发行包哈希后生成对照视频、`validation.json` 和 `index.html`。这些文件按项目规则不提交公共仓库。

首轮整局回放的失败保留于 `guided-attempt1/gesture-audit.json` 与 `logs/attack-tempo-guided-attempt1.log`：输入序号 1727 在怪兽预警的防御姿态下误触发一次左拳。原因是刚发出另一手光弹的历史护盾锚点没有跟随双手收回，新的深度偏差借用了旧的出拳轨迹。已增加专项先复现失败，再让预警期间清晰、紧凑且等高的双手防御重新建立锚点；宽姿势、单手伸展仍走原有判定。没有降低整局回放的零误出拳要求。

第二次回放 `guided-attempt2` 没有持姿误出拳并完成了整局和续局，但“新防御在 700 ms 内取得控制”的专项没有取到新事件：快慢轨迹的胸前准备姿势可能在预警前已形成护盾。测试脚本改为先放手 300 ms，再送入带偏差的新防御；取得控制的事件按消费的姿态序号归因，不按日志送达时间判断。游戏没有因此缩短防御持姿门槛。

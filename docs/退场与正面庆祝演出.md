# 退场与正面庆祝演出

旧版胜利段落把哥尔赞围绕脚底整体翻转，腹部和尾巴随之陷地；连续网格测量得到最低点为 -0.8547 Unity 单位。英雄则持续背向玩家举拳，胜利字幕叠在画面中央。单张刚进入胜利时的截图不能暴露这些问题，因此本轮先保存了 6.5 秒完整旧版片段。

新版使用失衡、屈膝下沉、稳定落地和淡出的退场顺序。双腿通过骨骼约束留在原落脚处，爪臂随身体下垂，尾链调整角度以保持各节长度并避开地面。落地只触发一次扬尘、小幅镜头震动和原创低沉碰撞声。

英雄先等待怪兽落地，再分两步转向孩子：第一步以左脚支撑，第二步以右脚支撑，移动脚抬起后落回地面；同时举拳庆祝。镜头随后跟到英雄正面，五位英雄均保留头部、拳头和脚底的界面安全空间。体感胜利分数与星章移到左侧，合照提示延后出现在得分下方，让脚部也保持清晰可见。远景随庆祝镜头逐渐扩大覆盖范围，避免左侧露黑；战斗镜头的远景比例保留。

## 时间与流程

- 胜利后 0–0.24 秒：保留失衡起势。
- 0.24–1.10 秒：怪兽屈膝，双脚支撑；1.10 秒触地反馈只播放一次。
- 1.30–2.70 秒：英雄通过两次换脚转向镜头。
- 2.65–3.55 秒：怪兽淡出；随后完整展示英雄正面庆祝。
- 实际自动合照仍须等待胜利至少 6 秒且语音结束；原有取景、额外 3 秒准备时间、5 秒倒数、预览、重拍和再玩不变。

`VictoryMotion` 统一退场、转身和淡出时点，伤害与动作识别规则未改。开发回放的胜利观察期从 3 秒延长到 5 秒，用于截取完整正面庆祝，这不改变用户实际的自动合照等待时间。

## 复现

```sh
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.VictoryReview.After \
  -quit -logFile "$PWD/logs/victory-staging-after.log"
```

这轮完善胜利段落的连续动作和构图，不代表已达到参考机台的整体动作丰富度或影视级模型品质。帧率专项仍按用户要求后置。

# 格尔赞收爪与前臂转动（2026-09-28）

仅限制折腕角度，仍会留下双手同时掌心向下、手指偏平的轮廓。本轮改为略向内相对的收爪姿态：四指采用不同弯曲量，并适当分开；拇指沿其自身指向掌心的轴对合，不再与四指共用一个弯曲轴。

手掌朝向的修正围绕“肘—腕”轴进行，60% 的轴向转动由前臂承担，手腕承担余量。总修正最多 55°，沿用已有的 35° 折腕限制。领爪在接触时稍转回劈抓方向，另一只手保持收拢；腕部的攻击目标和战斗时点继续由原动作驱动。每帧保存并还原这层姿态，避免反复累积。

检查中还发现，手臂求解使用了上一帧根节点残留的呼吸朝向。即使以零时间重复渲染，指节也可能移动约 0.019 个场景单位。现在先建立当前帧的角色朝向和位移，再采样及求解手臂。12 组流程中，重复采样的最大指节位移约为 0.000001，低于 0.0001 的检查阈值。

## 对照与范围

`artifacts/claw-grip/index.html` 提供近景前后对照，以及实际构建的蓄力、左右爪击和护盾接触截图。基准提交为 `2bfc364c0f3aa70e488ac48a6a8b06a4f9ad669d`。

- 两侧共匹配 3176 个手部采样，攻击阶段、攻击编号及时间逐项一致。
- 修正身体朝向反馈后，同一时刻的手腕位置相对基准最多改变约 0.014 个场景单位；没有修改命中时点。
- 前后最大折腕角度均为 35°，没有用放松折腕上限实现新轮廓。
- 对照影片 4.8 秒、144 帧，剪去等待，包含待机及两次左右交替爪击；隐藏背景和英雄以便检查手部。编码为 30 FPS，不代表当前运行帧率。

`ClawPoseReview.Release` 通过：左右攻击与两次防御；15／30／60 Hz 下各四组连续攻防、普攻及必杀、腾空中暂停恢复、新局复位，共 12 组稳定性检查；六组爪击光迹时序、接触颜色和中断清理检查。

旧 `RiggedReview.ValidateMotion` 的英雄手部单帧位移检查在本轮修改前后均失败，基准失败日志保存在 `logs/claw-grip-baseline-rigged.log`；当前版本也在本轮第一次综合检查时触发了同样的异常。基准复核用已提交的原始 `RiggedActor.cs`，完成后恢复本轮文件；没有把这个旧检查计入通过项，也没有调宽其阈值。它仍需独立检查英雄动作衔接。当前版本另外运行实际 macOS 完整战斗验证。

## 复现

1. 修改前执行 `ClawPoseReview.Before --claw-output <仓库>/artifacts/claw-grip`，保存当时的审查脚本到 `before/ClawPoseReview.cs`。
2. 当前版本执行 `ClawPoseReview.Release --claw-output <仓库>/artifacts/claw-grip`。
3. 执行 `bash scripts/build_macos.sh`，再执行 `scripts/cinematic_player_check.py --hero Tiga`。
4. 执行 `scripts/guided_player_check.py --output artifacts/claw-grip/guided --log logs/claw-grip-guided.log`；将运行前后的程序集及资源摘要保存为同目录 `build.json`。
5. 执行 `scripts/encode_claw_grip_review.py --player <本轮实战目录> --guided artifacts/claw-grip/guided`。脚本核对源码、时序、构建摘要后生成对照页。

本轮改善手部轮廓和动画求解稳定性。源模型精细度、整体动作丰富度仍与参考街机存在差距，帧率专项继续后置。

后续跟进：上述英雄手部位移失败已在[迪迦出拳轨迹衔接](迪迦出拳轨迹衔接.md)中定位并修复。原因是右拳源动画与运行时插值叠加，新版在原检查阈值下通过；本页保留当时发现问题的记录。

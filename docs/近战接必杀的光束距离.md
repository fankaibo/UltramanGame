# 近战接必杀的光束距离（A-20261011-95）

对照参考街机连击画面与当前发行包 `beam-contact.png`，近战后的迪迦与哥尔赞仍挤在一起，必杀光束短到接近胸前光团。根因是近战保留的接近站位在 Beam 期间冻结，蓄力特写结束后仍直接贴身发射。

本轮让迪迦在 1.35 秒蓄力特写中的前 0.82 秒，分两步平滑退回远程站位。上半身继续原蓄力动作，摄影机跟随角色；切回双方画面时，脚步已经落稳、光线有清楚的发射通道。不改变输入识别、语音等待、蓄能、伤害或光线命中时机，其他英雄暂时保留原逻辑。

## 专项结果

从实际 15 次连贯普攻接大招，角色／舞台全程更新，不用直接设血量或只采样一张姿势。

数值单位为场景世界单位；逐帧位移随采样率变化，不是性能指标。全部采样 15 普攻、1 必杀，200 初始血量最终为 176，零时间重复姿势误差为 0。

同输入前后近战的 289 行动作／时间／血量／能量完全一致；远程起手的 289 行包括角色前进量、脚部高度和光束长度全部相同。初版曾让远程起手也接管脚步，产生约 0.10 单位脚部高度变化，已收窄启用条件；失败记录在 `attempt-1/`，没有将初版当成最终版交付。

`beam-before-after.mp4` 为连续 4.8 秒专项片段，左旧右新，包含蓄力、发射、命中和收招。近战旧／新 60 Hz 使用同输入、同随机种子；它是 Unity 固定时间步渲染，不是实际屏幕录像。

## 中途触发与暂停

普通退步为 0.56 秒；如果在途中触发必杀并突然套用 0.82 秒新曲线，会导致角色短暂向前回弹。最终实现保留已经开始的退步曲线，只有从静止近战站位发起必杀才使用新的时长。实际延迟触发采样中，退步期间前向位移为 0、无明显穿地，光束间距正常。

暂停会按原游戏规则取消尚未完成的大招。未完成的脚步曲线单独保留，恢复时继续收尾，避免脚位重新回到同一点。先前暂停测试失败已记录在 `logs/a95-check-boundary.log`，修复后的 `logs/a95-check-release.log` 为 46 Python + 1550 核心／桥接检查通过。最初前向位移检查包含上一拳收招到大招的入口一帧，误把正常的 0.04245 单位收招位移计入退步回弹；现检查从退步开始后的 Beam 帧，保留整体最大根节点步长检查，未放宽原阈值。

# 扫描碎石与落地表面

A-20261010-72，2026-10-10；实现 `b281081`，对照 `e1f7d98`。

## 画面改变

重踏、英雄倒地、怪兽后撤与胜利落地的碎石，原来使用 20 面的程序网格和块状随机色。现在使用项目已有两款 CC0 扫描岩石的简化网格，各 320 个三角形，保留原 UV、颜色、法线和 AO／粗糙度贴图。表面颜色压为冷灰色，与现有火山岩场地相配；轮廓有长短、凹缺和不同断面。

两份网格和两份材质由 72 个碎石对象共享，复用场景已有的扫描贴图。普通落地最多启动 18 块，重踏波启动 48 块，池全部占用时合计 23,040 个三角形。飞行、回弹、逐顶点底面支撑、尘土、音效和淡出时钟沿用原规则。本项没有修改手势、伤害、英雄手臂、镜头或合照。

这改善的是地面接触细节，并不代表已达到参考街机整体动画与画质。总体进度仍为 70.2%，稳定帧率与内存专项按用户要求后置。

## 素材与复现

来源为项目已有的 Poly Haven `rock_07`、`rock_09`，作者 Jenelle van Heerden，CC0-1.0。原始来源及散列在 `Resources/Environment/ScannedRocks/sources.json`；衍生网格、三角形数量和来源散列在 `Resources/Environment/GroundDebris/sources.json`。

```bash
.cache/character-tools/Blender.app/Contents/MacOS/Blender \
  --background --factory-startup --disable-autoexec --python scripts/bake_ground_debris.py
ULTRAMAN_GROUND_REVIEW="$PWD/artifacts/scanned-debris-20261010" \
  /Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.GroundImpactReview.ScannedRelease -quit \
  -logFile "$PWD/logs/scanned-debris-reimport.log"
```

`GroundDebrisImport` 在导入时将网格半径规范为 0.9，仅这两份小网格保持 CPU 可读，以计算旋转后的底面。不会将大场景扫描模型改成可读，或生成额外纹理副本。

## 失败记录与更正

第一次离屏渲染发现 FBX 父节点保存了单位缩放，直接取网格会缩小 100 倍。初始资产检查只有半径上限，错误地通过；随后 GPU 可见性检查以 `stonePixels=1` 拒绝该结果。补上半径下限并在模型导入阶段规范化顶点后，通过检查。Unity 缓存还需要一次明确重新导入；导入器增加版本号，复现入口强制重新导入两份衍生模型。

无效画面保留在 `failed-unit-scale/`，失败日志保留为 `logs/scanned-debris-assets.log`、`scanned-debris-after.log`、`scanned-debris-final.log`；最终专项以 `scanned-debris-reimport.log` 为准。Blender 首次在沙箱中退出 139，重新以所需本机权限读取相同资产成功，源文件散列未变。

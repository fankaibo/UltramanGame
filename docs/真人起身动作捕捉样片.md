# 真人起身动作捕捉：样片、接触修正与接入

A-20261010-73。工具基线 `1d0229e`，样片提交 `45f3e3c`，运行时接入 `9d09302`。已完成五英雄支撑校准、实际战斗起身及自然前伸手位衔接；Release 构建／签名和实际 74.44 秒整局通过，157.2 秒完整合照续局通过。下文保留初版样片的问题，续轮修复和发行证据见文末。

## 初版样片：为什么先做转换验证

现有 Hurt 动作片段只有少量关键姿势，起身主要由程序设置腿和支撑手的位置。引入真人动作捕捉有望改善重心转移，但直接套用关节旋转会受到不同坐标轴、初始姿势、骨骼比例和父子关系的影响，不能仅因成功导入便认为自然度已经改善。

## 素材来源与范围

- [CMU subject 140](https://mocap.cs.cmu.edu/search.php?subjectnumber=140)：140_03，侧身躺地起身，120 Hz。BVH 文件来自 [Bruce Hahne 转换版镜像](https://github.com/una-dinosauria/cmu-mocap)，其中第 0 帧是额外的校准姿势，不能当作动作首帧。
- 对照检查 90_18 RugPullFall，约 3.28 秒；该片段只包含失衡倒地，**没有起身**，本轮未拼入动作。
- [CMU 使用说明](https://mocap.cs.cmu.edu/)允许研究与产品使用，禁止直接转售数据，包括转换后的数据。原始数据获得 NSF EIA-0196217 支持。转换作者没有附加使用限制。原始 BVH 和转换说明仅在本机 `.cache/mocap-cmu/`，没有上传公共仓库。
- CMU 明确提示手部、脚趾数据可能有噪声，手指并非实际捕捉；本轮不宣称还原了手指或真实手掌接触。

## 初版样片的实现和观察（45f3e3c）

新增 `inspect_mocap_bvh.py` 解析 BVH 层级、通道顺序和世界坐标，并输出源动作图。其 FK 结果已与 Blender 自带 BVH 导入器的第 901 帧对照，Hips、Head、LeftFoot、LeftLeg 位置一致（按 Y-up/Z-up 换轴）。

新增 `prepare_recovery_motion.py` 取 140_03 的第 350–780 帧，每四帧采样并保留最后一帧，109 个样本、3.5833 秒。用脚趾的朝向统一末帧朝前，转换左右轴；保留每个样本的实际时间，末尾不足四帧时不伪装成等间隔。源文件 SHA 写入衍生 JSON。

Editor 专用 `MocapRecoveryReview` 按髋、胸、上臂／前臂和大腿／小腿的解剖方向映射现有五个模型，而非直接复制原始欧拉角。较早的直接旋转样片出现手臂向后折、躯干后仰；改用几何方向后，已能看到收腿、蹲起和起立的完整顺序。测试类和文件都没有进入运行时资源路径。

连续采样同时发现，固定踝高并不等于脚底贴地。五个模型均仍有部分网格穿地，不能发布：

| --- | ---: | ---: | ---: |
| 迪迦 | 109 | -0.20329 | 0.19154 |
| 梦比优斯 | 109 | -0.24850 | 0.18605 |
| 赛罗 | 109 | -0.24397 | 0.18249 |
| 捷德当前临时模型 | 109 | -0.16284 | 0.17691 |
| 格力乔 | 109 | -0.22728 | 0.18451 |

数值为场景单位和约 30 Hz 的源动作采样，不是帧率、人体识别精度或自然度评分。最低点检查覆盖实际烘焙蒙皮顶点。泽塔／德凯没有真实骨骼模型，未纳入此样片。

本机证据 `artifacts/mocap-recovery-20261010/`：原始动作图、早期失败 `prototype/` 与 `prototype-reflect-x/`、几何映射中间样片 `prototype-anatomical/`、最终连续诊断 `anatomical-sequence/`、文件身份 `identity.json`。`tiga-prototype.mp4` 是 1280×720、109 帧、30 FPS 离线样片，约 3.63 秒，**并非实际游戏包回放**。

## 初版样片提出的接入条件（后续结果见文末）

1. 以真实鞋底／支撑手几何校准接触，并核查髋节点是否为全部肢体的祖先；不能仅抬高骨盆来掩盖穿地。
2. 保留支撑脚的世界位置，处理不同体型、膝盖弯曲平面、手腕噪声及近乎伸直时的旋转翻转。
3. 将落地、起身和自然前伸待战姿势连成同一段，检查压缩到游戏节奏后的动作速度。源动作 3.58 秒不能直接塞进当前短起身窗口。
4. 通过 15/30/60 Hz、重复采样、暂停、插入攻击／防御、新局恢复、五英雄完整画面和发行版回放，才允许替换现有动作。

## 2026-10-10 续轮：接入真实战斗（9d09302）

上一轮工具提交 `45f3e3c`，状态仍为未接入样片。本轮继续完成接触校准和运行时接入，前面的失败记录不覆盖。

- 按实际鞋底几何设置足底平面。统一场景地面与角色根节点偏移，先让骨盆进入双腿能够到达支撑脚的位置，再解算腿部；坐地阶段按模型体积提高髋部，同时保持脚目标不动。
- 根据原始脚部高度与移动速度识别支撑段，缓入／缓出固定脚位置。五英雄离线各 109 帧，最终最低蒙皮顶点 Y 为 0.00190–0.00200，足部目标误差低于记录的五位小数精度。原来的穿地与够不到脚目标问题都有独立失败样片。
- 烘焙为总计 758,132 字节的五个角色专用数据文件，附来源与 SHA。运行时仅在该角色第一次起身时载入，逐帧插值；不在游戏帧中烘焙网格或重新解算源骨骼。
- 新增 `CapturedRecoveryPose`，保留受击和落地的原有前段，接上收腿、移重心、起立。受击恢复时长由 1.65 秒改为 2.55 秒，让约 3.58 秒的源动作在 1.76 秒的主动作窗口内可读；倒地期间仍不能攻击，落地只计一次。
- 起身最后直接混合到自然前伸待战姿势，避免恢复结束时手臂突然跳回。多层骨骼改为按最终世界朝向混合，修正捷德曾在中间帧躯干翻折的情况；手脚端点与朝向共同过渡，保持支撑。

实际战斗时钟下，五英雄 × 15/30/60 Hz 全部通过；重复采样误差为 0，单次受击／落地、站稳立即防御、暂停／恢复／反击和新局恢复均通过。起身阶段（动作龄大于 0.70 秒）五英雄 60 Hz 的最低顶点均约为 0.002。捷德在原有受击前段仍保留约 -0.019 的脚尖最低点，在原有 -0.05 的场景检查容差内；未把这项前段误差说成完全消失。Tiga-60 从起身末段进入下一动作的最大记录步移降到约 0.06 场景单位，第一帧 Idle 不再有此前样片的约 0.54 跳变。

证据：`runtime-anatomical-handoff/` 为最终 15 组运行时审查，`gameplay/before/` 为接入前的原版画面；`runtime/`、`runtime-ready/`、`runtime-world-handoff/`、`runtime-contact-diagnostic/` 保留中途暴露的问题。`recovery-comparison.mp4` 按落地时刻对齐两侧，保留 1.65 / 2.55 秒的时长差，片尾不足部分定格。`runtime-identity.json` 绑定源码、视频和检查指标。

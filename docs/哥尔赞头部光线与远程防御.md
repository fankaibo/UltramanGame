# 哥尔赞头部光线与远程防御（2026-09-29）

当前战斗已加入左右挥爪与第三次重踏，但长局中仍会反复看到相同的近身攻击。此轮加入头部蓄能、远程光线、盾面接触和收势，为同一个防御动作提供不同的战斗演出。能力依据是[圆谷官方哥尔赞资料](https://tsuburaya-prod.com/encyclopedia/golza)介绍的头部超音波光线；动画、紫色特效与声音由项目实现，没有提取影视音视频。

## 行为

每六次攻击中的第四次使用头部光线，首次在第 4 次、再次在第 10 次出现；第 3、6 次等重踏仍保留。原有语音预警、语音后 3 秒反应时间、动作识别和防御判定不变。

哥尔赞蓄力末段站稳双脚、张开胸前双爪，额头逐渐发光。攻击开始 0.16 秒后发射，光线在原有 0.4 秒接触时点抵达盾面或英雄，0.70 秒开始减弱，0.92 秒熄灭。它只沿用一次原有防御／受击结算，不会因持续光线重复造成伤害；没有防御时仍进入儿童友好的倒地与恢复流程。

发射点通过射线绑定额头网格三角形，运行时只蒙皮计算三个顶点，随头部动画移动。第一版偏低的眼部发射点已经替换。双脚固定在原站位，躯干小幅后坐，双臂不再继承挥爪前冲；动作层与重踏共用恢复机制，受击时从实际姿势过渡。收势结束后不会再次抬手。

镜头保留双方及完整盾面。盾面接触转为蓝色闪光和涟漪；爪迹、前冲扬尘和冲刺音在这次远程攻击中不播放。新原创循环音跟随光线强度启停，暂停、静音、切入英雄必杀及重新开始会清理。原英雄必杀聚能颜色保持不变。

## 验证

基线为 `fb8799a39a5d05add062e8fc574e5b29685efb8e`。`artifacts/monster-ray/index.html` 提供原来第四次挥爪与现在头部光线的同步对照，以及五英雄防御画面和实际应用截图。两段都是 159 帧、5.3 秒离线渲染；逐帧攻击阶段、时间、血量、防御和受击计数完全相同。30 FPS 是对照视频编码速率，不是游戏性能声明。

29 组编辑器场景检查通过：迪迦在 15、30、60 Hz 下验证持续防御、未防御、晚举手、提前放手、蓄力中出拳、暂停、重开及晚到语音延长预警；另外四位英雄完成防御构图检查，第 4、10 次攻击验证两次独立发射。脚位置在采样精度内稳定，手腕与前臂夹角不超过 35 度，没有脚底穿地。相同时间重复采样骨骼最大差不超过 0.000001 世界单位；光线与挥爪效果不会重叠。

重踏既有场景检查、五英雄必杀接触和恢复检查，以及 33 项 Python、324 项 C# 核心及 327 项集成检查通过。原生 macOS 构建与本地签名通过；新应用完成 98.22 秒整局回放：32 拳、2 次英雄必杀、3 次防御、1 次受伤、暂停和胜利退场。第 4 次怪兽光线实际发射一次，声音启动和停止各一次，额头网格绑定成功。

构建程序集摘要为 `5cce830e9d9fbe7696e2d272547ebffdadd461ca3d42f62444132dbc6a8044cd`，资源包摘要为 `804335bea41031d66d5b5fa997e068d82586891d6a5ac1d053ab551e365f3403`。

同一游戏包另通过 138.0 秒无键鼠流程，自动合照两次、重拍、取景／预览断流恢复、举手变身并开始第二局。95 帧防御深度噪声、11 帧大招深度噪声期间误触普攻为 0，成功防御与英雄必杀各两次；保存 PNG 与预览中心区域颜色差 P99 为 0。引导测试前后构建摘要一致。上述测试使用合成姿态和 TEST 人物，没有保存真人图像，也没有调用合照 AI。

## 复现

```sh
Unity -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.MonsterRayReview.After \
  -quit -logFile "$PWD/logs/monster-ray-final.log"
bash scripts/check.sh
bash scripts/build_macos.sh
.venv/bin/python scripts/cinematic_player_check.py --hero Tiga --slam --ray
.venv/bin/python scripts/guided_player_check.py --gesture-wobble \
  --output artifacts/monster-ray/guided --log logs/monster-ray-guided.log
.venv/bin/python scripts/encode_monster_ray_review.py
```

比较所需的 `before` 目录必须先在基线版本下用同一渲染驱动生成，不能用新代码重新生成旧画面。编码脚本核对基线 Git 内容、当前渲染源码及两次原生流程所用的程序集和资源摘要。引导测试现在直接保存运行前后摘要，开始时删除旧的通过结果，避免中断后误用上次测试。

本轮完成一种新的战斗演出，不代表整体街机目标已经完成。哥尔赞仍使用原有模型；真人摄像头识别、真人合照硬边与光照融合仍待后续验证和改进。帧率专项继续后置。

# 双角色 3D 实战接入

2026-09-09，在用户确认“下一步，继续”后，将样片中验证的哥尔赞骨骼模型接入实际摄像头战斗。启动入口仍为项目根目录 `启动游戏.command`，构建输出仍为 `unity/Builds/TigaTraining.app`。

## 这轮改动

- 哥尔赞资源从 Editor 候选目录移动到 `Resources/Characters/Golza`，由实际 `Battle` 状态驱动蓄力、跨步挥爪、受击与退场；57 根导入骨骼，6 段烘焙动作。Editor 样片改为共用该素材。
- 迪迦保留 8 段实战动作，在左右拳中加入后脚支撑、前脚抬起/落地和回收。普攻仍在 0.12 秒命中、0.38 秒结束；怪兽仍在反击的 0.4 秒接触、1.05 秒结束，不改变输入和计伤时钟。
- 双方间距缩到约 2.70 单位。迪迦 `(-.955,0,-.555)`，哥尔赞 `(.955,0,1.355)`，仍为斜向 45°。普攻和怪兽前冲均为 0.75 单位，减少原先整块角色快速滑行的距离。
- 哥尔赞按骨盆定位，避免长尾改变站位中心。后脚抵消前冲位移，屈膝时抬起尾根，修正尾部穿地。语音提示期间保持清晰蓄力姿势，在最后一秒完成攻击准备。
- 增加 512×512 的角色轮廓阴影，最多每秒更新 30 次，只绘制角色层；透明地面保留城市背景。退出时释放纹理、材质和辅助相机，没有添加深色圆盘。
- 挥爪特效跟随怪兽右手；光线与特写蓄光跟随迪迦前臂。先更新骨骼，再更新特效，避免滞后一帧。大招继续保留专属放大镜头、招式字幕和本机原声。
- F5 与游戏包内补齐哥尔赞署名。macOS 打包最后写入署名，按动态库到外层应用的顺序完成本地临时签名并严格校验；没有使用开发者账号，也不代表已公证发布。

## 验证证据

- `logs/live-3d-checks.log`：14 项 Python、184 项 C#、3 项额外跨进程检查，共 201 项，全部通过。
- `logs/live-3d-review.log`：真实游戏状态驱动的 300 帧实战，17 次普攻、1 次格挡、0 次受击、1 次光线后胜利。两名模型实际加载，手臂/腰部变形、脚步、落地阴影、暂停清理、对角线前进及大招镜头检查通过。
- 角色最低蒙皮位置从首次发现的 -0.124 单位修正到 -0.006；怪兽前脚抬升 0.129 单位。相邻帧英雄手部最大位移 0.769 单位，包含快速出拳和动作转换。这是形变检查，不等于动画力量感已经满足最终目标。
- `artifacts/animation-review/`：实战攻击、格挡、反击、退回、暂停和大招特写的实际 Unity 渲染图；`artifacts/rigged-combat/`：连续战斗帧。
- `logs/live-3d-player.log`：已构建的玩家应用以后台模式连接合成姿态服务，加载迪迦 200 骨/8 动作、哥尔赞 57 骨/6 动作，收到变身与普攻事件，默认血量为 50。测试持续 18 秒后清理游戏和服务进程，没有打开真实摄像头。该检查不能代替孩子试玩，也没有重新测量小米电视投屏延迟。
- `logs/unity-build.log` 与 `logs/live-3d-build-driver.log`：macOS 开发包构建；`codesign --verify --deep --strict` 验证本地签名。

## 复现与保留的边界

使用 `scripts/prepare_tiga.py --live-combat --export` 和 `scripts/prepare_golza.py --live-combat --export` 重新烘焙后，将 FBX 复制到各自的 Resources 目录。输入路径、官方转换工具和原始素材校验值见前一轮 [样片记录](双角色战斗样片.md) 及各角色 `ATTRIBUTION.txt`。运行 `UltramanGame.Editor.RiggedReview.ReviewLiveRelease` 可检查完整实战与镜头，最后使用 `bash scripts/build_macos.sh` 构建并签名。

原有动作识别、引导语音结束后的 3 秒等待、默认 50 次血量、15 拳蓄满、光线伤害 9、相机小窗、音乐导入与胜利合照均保留。合照仍用正面迪迦插画。

哥尔赞原贴图只有 256×1024，城市仍是平面背景，精细皮肤、连续步法、腰肩力量和整体演出与参考视频仍有差距。此前长时间真实摄像头运行的 GPU 异常未在本轮修复；本轮没有宣称完成长时间稳定性测试。

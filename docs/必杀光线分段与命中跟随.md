# 必杀光线分段与命中跟随

本轮继续优先完善街机演出，帧率优化后置。旧版在发射第一帧直接显示整条白色光线，持续火花固定在场地坐标；哥尔赞后仰后，光线与身体接触处会错开。键盘练习界面的招式标题还会挡住举起的手臂。

新版保留蓄力近景，然后依次表现光束飞出、胸口命中、持续放射和淡出收束。光束由蓝色外层、白色窄芯和沿射线移动的纹理组成；光束末端与局部补光跟随胸部骨骼，命中前不产生怪兽身上的连续火花。必杀受击使用较弱的蓝色材质反馈，普通拳击保留暖色反馈。

两种输入模式都在画面下沿显示招式名；键盘模式发射期间暂时收起动作卡片，体感模式暂时隐去正上方的积分条，避免遮住举起的手。家长控制入口仍然可用。已确认的原声、动作识别、儿童反应时间、50 次默认血量、15 次普攻充能和一次必杀 9 点伤害不变。

## 时序与接触点

- `BeamCloseup` 仍为 1.35 秒特写，期间保留输入检查，战斗时钟暂停。
- 特写结束后的动作时钟到 0.28 秒开始发射，到 `Battle.BeamHitSeconds`（0.45 秒）抵达目标，与原有唯一一次伤害结算一致。
- 接触后持续发光和产生火花，从 1.22 秒开始收束，到原有 1.5 秒动作结束清空光束。
- 胸口目标在初始姿态中保存为胸骨局部坐标。实际反冲测试中目标移动约 0.46 Unity 单位，光线跟随这个位置，发射端始终绑定当前英雄前臂。
- 暂停、跟踪丢失进入暂停、重新开始均走现有清理路径，没有创建额外战斗阶段。

## 复现

```sh
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.FinisherReview.After \
  -quit -logFile "$PWD/logs/finisher-after.log"
```

`Before` 只保存当时源码的表现，不会切换历史版本；不要在新版上重新生成并冒充旧版对照。

这是现有骨骼动作之上的必杀表现改进，角色原始模型、动作丰富度和整局镜头编排仍与参考街机存在差距。自动回放也不代替孩子真人操作和电视显示验收。

## 2026-09-30 最后一击与胜利衔接

复核收尾发现：此前的光线分段仅在非致命伤害时完整。当命中使怪兽血量归零，`Battle` 在 0.45 秒命中帧直接切入胜利，光束被隐藏，英雄提前换成庆祝动作。基准 `0bc2fdd` 的实际 Unity 连续渲染显示，最后一束可见光线的动作时钟仅到 0.4333 秒，胜利在 0.4500 秒触发。新增核心回归也在修改前失败，见 `logs/final-strike-before-checks.log`。

现在血量仍在原命中时刻结算，但战斗会保留已接受的最后一次动作，等到普攻 0.38 秒／大招 1.5 秒结束后才发出胜利事件。归零后怪兽立即停止攻击，新的出拳、防御和大招意图不能取消或替换收尾，伤害与能量不会重复计算。暂停和失去跟踪时冻结动作时钟，恢复后继续剩余释放；重新开始仍清空旧战斗。第 15 拳同时击败怪兽时保留能量计数，但不再发出“能量满了，释放光线”的矛盾提示。

哥尔赞进入倒地前保存实际可见的受击骨骼和位置，用 0.34 秒衔接到倒地动作，减少从后仰姿势突然跳回直立的过渡。致命连击不再开始一个马上被倒地覆盖的上挑腾空。英雄胜利时计时器回到正常亮度，不继续沿用最后大招的发光强度。胜利语音和自动合照的六秒准备计时从动作结束后的胜利事件开始，既有拍照、重拍与举手续局手势保留。

`logs/final-strike-checks.log`：36 项 Python、657 项核心及含通信的 660 项检查通过，覆盖 15／30／60 Hz 的最后一击、暂停恢复、混合姿势输入、单次伤害、敌方停止反击及能量提示。原有测试中写死的胜利等待时间改为包含完整释放时长，并增加动作已完成断言。

`logs/final-strike-continuity.log`：五位英雄均只命中、释放和胜利一次，最后可见光线时钟为 1.4920 秒，胜利事件为 1.5087 秒（60 Hz 步进）。哥尔赞进入倒地首帧的手部位移为 0.0046 场景单位，最低网格点为 -0.0055，零时间重复采样的骨骼位置差为 0。新的九秒同输入对照保存于 `artifacts/final-strike/`，离线 30 FPS 不代表实际运行帧率。

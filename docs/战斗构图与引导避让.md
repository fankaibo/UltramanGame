# 战斗构图与引导避让（2026-09-28）

本轮按“街机体验优先、帧率专项后置”的方向修正动作呈现。之前的普通战斗镜头过紧，迪迦脚部进入底部提示区域；五拳连击推进时甚至裁掉小腿。必杀返回和腾空追击结束时，重新出现的引导也会挡住脚步。

普通战斗视角在保留脚部和底部引导安全边界的前提下收紧到约 27.8°，让角色在电视画面中更接近参考街机的主体比例；底部引导固定为 29px 窄轨道，出拳瞬间的额外变焦仍受控。五拳连击仍有侧向移动和推进，但改为完整双人构图，投影放大约 6%；腾空追击镜头为落地和脚步恢复留出下方空间。专属变身、必杀人物特写及怪兽蓄力镜头保留。必杀发射和怪兽反应的专属近景允许按镜头设计裁切，普通构图检查只覆盖近景退出后的返回帧。

底部引导从虚拟 1280×720 坐标的 `y=638、高65` 改为 `y=662、高49`；文字 18 改为 17，1080P 显示相当于约 25.5 像素。必杀名称也移至底部留白。按键／体感切换、设置、暂停及重新开始入口继续保留。

## 验证

`PlayfieldReview.Release` 通过五位英雄共 28 组普通出拳、五拳连击、十拳腾空追击和必杀返回检查。迪迦分别采样 15、30、60 Hz，其余英雄采样 60 Hz。检查实际蒙皮顶点在画面中的位置，包含连击后的快速第二拳和回到站位：

- 非专属特写画面内，角色不被画框裁切，也未进入顶部血量板、底部引导条及右下取景窗口。
- 普通站位下角色高度约为画面高度的 69%–70%，保留电视观看所需的主体大小。
- 背景覆盖全部画框；相同时间重复渲染不会推动镜头。
- 连击、怪兽攻击和蓄力的 63 组暂停、换局、必杀、引导延时与恢复检查通过。

引导条检查按持续占用区域计算，比实际偶尔隐藏的引导更严格。顶部检查针对血量板，没有将整个天空都视为不可用空间；角色在两块血量板中间仍可以正常运动。这些检查覆盖列出的动作，不代表任意未来动画都自动满足边界。

另运行既有 `ComboCameraReview.Framing`。其旧规则要求至少 8% 放大并禁止进入整个顶部 14% 区域，已随新设计更新为至少 5% 放大、实际血量板零重叠；新增检查同时覆盖全部身体和底部空间。

## 对照与复现

`artifacts/playfield/index.html` 包含 20 秒前后对照：普通出拳、连击、腾空追击、必杀各 5 秒。基准为 `d7ef992e4cdaba869cf4690523012925d59d7b25`。四段的输入与战斗状态 CSV 必须逐字一致，生成页面前校验源码摘要和原生构建摘要。对照视频无 HUD，页面另外展示当前打包版的完整 HUD 截图。

离线视频采样 30 FPS，不代表实际游戏帧率。本轮没有调整动作识别、伤害、能量或提示反应时间，也没有开展帧率优化。

复现步骤：

1. 基准版本执行 `PlayfieldReview.Before`，并保存当时的审查脚本到 `artifacts/playfield/before/PlayfieldReview.cs`。
2. 当前版本执行 `PlayfieldReview.Release` 和 `ComboCameraReview.Framing`。
3. 执行 `bash scripts/build_macos.sh`。
4. 执行 `scripts/cinematic_player_check.py --hero Tiga`。
5. 执行 `scripts/guided_player_check.py --output artifacts/playfield/guided --log logs/playfield-guided.log`，保存运行前后的程序和资源摘要为该目录 `build.json`。
6. 执行 `scripts/encode_playfield_review.py --player <本轮实战目录> --guided artifacts/playfield/guided`。

这是动作可读性与构图的一次修正。角色细节、更多攻击动作和场景丰富度仍与最终参考街机存在差距。

# 战斗演出升级验收

本轮从 main bdbb1fa 开始，原版画面保存在 artifacts/cinematic-before。目标是让已能玩的家庭体感游戏拥有统一的立体舞台和连续、有重量的战斗演出。

## 必须保留

- 迪迦近左、哥尔赞远右的斜向站位，原有城市天际线；不重新增加脚下的深色圆盘。
- 本地摄像头识别、儿童动作容差、中文引导后的 3 秒反应时间、断线恢复。
- 默认 50 次普通攻击血量、15 次普通攻击蓄满大招，可调整血量；轻度反击且无失败。
- 已确认的迪迦原声、音乐导入、镂空合照与保存预览。

## 本轮完成标准

1. 城市地面具有实际空间透视、材质和接触关系，角色受同一组环境灯光影响。
2. 普攻、前冲、防御、受击、大招均有对应的连续运动和分层特效；避免简单光柱、彩色球堆砌。
3. 命中反馈加强但不造成儿童输入丢失；暂停和重新开始会清理镜头及特效状态。
4. 大招保持角色特写、原声、蓄力、发射、怪兽反馈和回到战场的完整时序。
5. 自动运行默认 50 血量的完整战斗，验证 15 拳蓄能、反击、防御、受击恢复和胜利；保存实际 Unity 渲染的画面及录像。
6. 本机回归检查、Unity 编译构建及运行检查通过，提供可试玩构建与可审查的 GitHub 版本。

素材本身的局限需要如实说明：当前哥尔赞来源模型为低面数、低分辨率贴图；灯光和特效不能等同于重新制作影视级角色。自动输入验证不等同于孩子本人再次试玩。

## 已实现的演出

- 立体石板地面、湿润表面反光、滨水灯带和实时角色阴影。城市背景改为场景中的固定平面，特写时与相机保持一致透视；没有新增圆盘。
- 使用实际天空环境反射，以及暖色主光、冷色轮廓光；保留原贴图，哥尔赞表面增加程序化微小凹凸。
- 迪迦原有 8 段动作重新烘焙，增加收拳时反向预备、转腰与前倾；仍以 0.12 秒命中、0.38 秒完成普攻为规则基础。
- 命中时仅将接下来的 55 毫秒（大招 85 毫秒）战斗时间减慢，输入仍每帧处理。暂停、失去追踪和重开立即清理该效果，不使用全局 Time.timeScale。
- 分层光线、旋转聚能弧、屏障边缘光和扫描纹理、短促火花、接触闪光、地面冲击波和局部动态灯光。摄像机采用一次衰减的微小后坐，避免持续晃动。
- 开局前在小尺寸离屏画面预渲染真实模型和效果，减少首次使用时的着色器卡顿。离开场景会回收运行时创建的材质和纹理。

## 本机检查

- `logs/cinematic-checks.log`：26 项 Python、201 项 C# 与 3 项额外跨进程检查，共 230 项通过。新增检查涵盖命中减速期间接收攻击、追踪暂停、重置和减速边界。
- `logs/cinematic-release-render.log`：双角色连续动作、出拳站位、脚掌高度、反击接触、特写裁切及暂停清理检查；随后以普通输入从 50 血量自动完成一局。
- `artifacts/cinematic-combat/validation.txt`：60.80 秒、1824 帧；32 次普攻、2 次大招、1 次防御、1 次轻度受击，以及中途追踪暂停和恢复。
- `logs/cinematic-player-check.log`：构建后的真实 macOS 玩家进程在 67.42 秒内完成检查，同样验证整局、两次迪迦战吼与语音之后的 3 秒反应时间。两个战斗采样窗口为 59.5 / 59.6 FPS，最慢帧分别为 32.4 / 21.5 毫秒；启动资源预热的长帧均发生在等待入场阶段。帧率结果保存在 `artifacts/cinematic-combat/player-validation.json`。
- `logs/cinematic-recovery-check.log`：同一最终构建运行中注入识别子进程退出，12.4 秒内完成整项检查；服务恢复后血量 49、能量 1 保留，继续攻击，无需重新变身。使用合成输入，未占用家庭摄像头。
- `logs/cinematic-photo-check.log`、`logs/cinematic-photo-render.log`：38 / 38 帧合成人像通过透明通道和通信检查，Unity 合成 1920×1080 成片通过；未保存真人照片。
- `logs/cinematic-build.log`、`logs/unity-build.log`：本机开发构建及嵌套原生库签名验证。

自动输入只用于验收；日常启动不会启用该模式，也不会自动攻击或修改用户设置。相机原生 CPU 20 分钟压力测试属于上一轮稳定性结果，本轮没有重复该测试或录制家庭摄像头。

## 复现

```bash
bash scripts/check.sh

Unity -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.CinematicReview.RenderRelease \
  -quit -logFile "$PWD/logs/cinematic-release-render.log"

python3 scripts/encode_cinematic_review.py \
  --baseline .cache/cinematic-baseline/artifacts/rigged-combat
bash scripts/build_macos.sh
.venv/bin/python scripts/cinematic_player_check.py
```

完整录像：`artifacts/cinematic-combat/full-battle.mp4`。简短演示：`artifacts/cinematic-combat/battle-highlights.mp4`。录像帧直接来自 Unity 的实际模型和运行时代码；音轨使用项目配乐、效果和本机原声。旁白队列与音乐导入在实际玩家进程中另外验证，渲染录像不冒充一次真人试玩。

升级前对照从提交 `bdbb1fab81e689fc8ee792f97841e8fe0804868e` 的源码导出到独立临时工程，再渲染相同的 10 秒动作脚本。左侧为升级前、右侧为升级后。最终对比视频保存为 `artifacts/cinematic-combat/before-after.mp4`。它比较本项目的两个版本，不把商场视频或未经验证的素材混作游戏输出。

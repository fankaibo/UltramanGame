# 近战防御与反击衔接

改动 A-20261009-59；实现 `5f55e55`；对照基线 `3f98e54`；2026-10-09。进度与剩余验收见 [开发任务看板](开发任务看板.md)。

## 问题与改动

之前远程出招有专门的手位交接，普通拳和腕剑转防御却先撤掉脚步、躯干、手臂的叠加姿势，再采样护盾动作。因此伤害规则已经进入防御，身体却在一帧内缩回原位置。五位现有英雄的修改前回放均复现：60 Hz 下，第一帧手腕最大移动 1.55446、身体根节点最大移动 1.25596 个场景单位。

新增 `HeroPoseHandoff` 保存玩家上一帧真正看见的整身骨骼姿势和位置。防御过渡持续 0.18 秒，身体、双臂和脚步一起回收；需要后撤的脚短暂抬起，支撑脚保持原位。每次重新采样先撤回本层，避免姿势累积。规则中的护盾即时生效，动画不会延迟保护；暂停时冻结过渡，新局清除旧状态。

专项还发现旧版收盾反击容易打空：旧护盾过渡持续到出拳命中之后，怪兽后仰时角色仍向原站位出拳。反击现在只使用短暂交接；以怪兽初始真实胸部蒙皮位置为基准，跟随当前后仰距离。若手臂仍够不到目标，用前后脚的短追击步补足距离，不拉长骨骼。腕剑、第五击和踢击保留各自的独立动作分支。

这轮没有修改识别阈值、血量、蓄能、伤害、护盾规则和出手快慢。`ReviewPlayback` 新增可选的验证输入：第一拳命中后举盾，再用另一只手反击；它使用普通输入接口，不直接改血量或动作时钟。

## 验证边界与过程

`MeleeGuardReview` 覆盖五英雄 × 15/30/60 Hz × 两档速度 × 左右手 × 三个取消时机 × 直接护盾／先意图后护盾，共 360 个场景。保存完整战斗状态轨迹和迪迦、梦比优斯的连续画面。

`HeroGuardHandoffReview` 覆盖五英雄和三种步长，检查左右快慢、立即防御、取消后无追加命中、暂停冻结、跟踪恢复、立即反击、实际蒙皮接地、手臂长度和新局复位。

最终 360 个场景与 15 组生命周期全部通过。前后 25,200 帧动作、护盾、伤害、能量和命中数一致；41 项 Python 与 916 项规则／姿态／通信检查通过。既有 `RosterPunchReview.CheckGuardTransitions` 和 `SurfaceImpactReview.CheckPunchRecovery` 也通过；泽塔、德凯未有真实模型，不计入五英雄实模结论。

实际蒙皮最低高度约 −0.0037，手臂长度误差约 0.000001；15 Hz 最快反击的命中帧距瞄准点最多约 0.734，扫掠段最多约 0.494。30/60 Hz 的最大扫掠距离约 0.397／0.429。这里记录的是几何采样范围，不能据此宣称每帧都精确接触。

过程中的失败日志均保留。最初反击距离检查既没有对齐英雄瞄准与怪兽后仰的更新顺序，也没有区分粗步长下的采样点和连续扫掠段；用旧版运行时代码复现后，确认旧版也存在反击距离不足，继而修正收盾交接与追击脚步。最终同时记录命中帧距原瞄准点的距离、两帧间扫掠距离，以及怪兽后仰后的距离。采用项目既有角色接触距离预算，不将单个数字等同于每帧精准触碰。

低帧率快速挥拳仍可能在两帧之间经过最接近的位置，不能声称其画面与高帧率相同。本轮解决的是动作切换和反击接近问题，未完成稳定帧率、影视级动画、真人儿童及电视现场验收。

## 复现

```bash
UNITY='/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity'
# before/ 是在 3f98e54 的运行时代码下保存的原版数据，不用新版覆盖。
"$UNITY" -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.MeleeGuardReview.Release -quit \
  -logFile "$PWD/logs/melee-guard-release.log"
bash scripts/check.sh
bash scripts/build_macos.sh --release
.venv/bin/python scripts/cinematic_player_check.py --hero Tiga --linked --guard-handoff
# 将本次验证 JSON 复制到 melee-guard-20261009/native/player-validation.json。
.venv/bin/python scripts/guided_player_check.py --hero Tiga --gesture-wobble \
  --gesture-entry-noise --output artifacts/melee-guard-20261009/guided \
  --log logs/guided-melee-guard.log
.venv/bin/python scripts/encode_melee_guard_review.py
```

本机证据位于 `artifacts/melee-guard-20261009/`，不提交公共仓库。对照视频左旧右新，先迪迦后梦比优斯，均二分之一速度展示；30 FPS 是离线输出规格，不是实机性能结论。公开仓库没有新增相机照片、音乐或密钥。

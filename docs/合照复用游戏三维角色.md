# 合照复用游戏三维角色（2026-09-29）

战斗已使用骨骼模型、环境反射和新战衣材质，但合照中的迪迦仍来自独立绿幕图片，另外四位英雄也来自预渲染 PNG。因此合照不会继承游戏内的材质改进，迪迦轮廓还会残留绿色。此轮让五位合照英雄直接复用所选游戏角色的模型和材质。

## 实现和边界

- `PhotoHero` 从 `AnimatedActor` 创建所选角色，采样原来的胜利动作，然后只烘焙一次当前网格。头盔、眼睛等刚性部件保留原模型。后续取景、倒计时和重拍不再播放或重新采样角色动作。
- 在完整可见网格上测量轮廓；头顶来自头部骨骼关联的顶点，肩线来自两侧上臂起点，举起的手不会被当成人的头顶。英雄仍固定在左侧、同一尺寸和脚底基准线上，只按身体参考调整右侧拍照人的比例。
- 合照使用独立的月光、柔和补光和火山轮廓光；渲染期间隔离战斗灯光对合照层的影响，随后恢复灯光掩码、启用状态、环境光、雾和反射引用。照片关闭后回到原战斗环境。
- 背景先绘制，3D 角色随后绘制，真人透明层最后绘制。1080P 和 2560×1440 继续可用，角色边缘使用 4x MSAA；预览仅在新取景帧到达时更新。
- `PersonMatte()` 隐藏整个英雄及背景，继续导出线性的人物专用蒙版；`CleanPlate()` 保留背景和 3D 英雄。AI 处理不会因为新角色而把奥特曼纳入人物修改区域。
- 模型导入保留运行时读取所需的顶点和骨骼权重，避免编辑器能够访问、实际玩家却被剥离的问题。编辑器资源所有者增加生命周期支持；关闭合照及销毁相机、根对象后，临时网格、材质、灯光和渲染目标均释放。

这一轮没有改动 `PhotoLayout` 的人物比例规则、动作识别阈值、血量或蓄能。没有上传真人照片或调用 AI。旧的图像资源仍保留用于项目历史，合照运行路径已不再读取它们。

## 对照与检查

修改前从提交 `f45c97b179f8cc79f6403cbd29b25215811ecf99` 导出旧迪迦合照。`artifacts/photo-3d/index.html` 提供相同背景和测试人物像素的前后对照，以及五位英雄的全身、半身和背景底图。圆形与蓝色矩形是合成比例测试图形，不是真人。

编辑器检查五位英雄的材质与实际战斗角色一致、每次取景及重拍后英雄变换不变、人物蒙版不含英雄。1080P／2K 的 RGB 合成与透明度 0、64、128、192、255 均通过；正常关闭、先销毁相机、先销毁根对象和重复关闭均通过。

`scripts/check.sh` 的 33 项 Python、324 项 C# 核心检查及包含跨进程通信的 327 项集成检查通过。这些检查保留了此前防御和大招意图优先、短暂抖动不被普攻抢占的回归覆盖。

macOS 构建与本地签名通过。实际打包版通过本机体感协议完成了 139.1 秒无键鼠流程：自动照片两张、重拍、倒计时中断恢复、预览姿态流中断恢复、举手变身和第二局开战。96 帧防御深度噪声及 12 帧大招深度噪声期间误触普攻为 0，成功防御与必杀各两次。预览和保存 PNG 的中心区域颜色差 P99 为 0；已经查看真实应用的合照预览及返回战斗画面。

测试使用合成姿态和 TEST 人物，照片先由游戏写入 Downloads，再移入忽略的验证目录。没有保存真人照片、没有调用 AI，也不能代替孩子真实摄像头体验的确认。

复现：

```sh
Unity -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.PhotoHeroReview.Run \
  -quit -logFile "$PWD/logs/photo-3d-review.log"
bash scripts/build_macos.sh
.venv/bin/python scripts/guided_player_check.py --gesture-wobble \
  --output artifacts/photo-3d/guided --log logs/photo-3d-guided.log
.venv/bin/python scripts/encode_photo_3d_review.py
```

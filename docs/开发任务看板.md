## 当前执行优先级：先完成迪迦整局（用户于 2026-10-10 调整）

**当前主线只以迪迦＋哥尔赞打磨完整街机体验。其他奥特英雄的模型、动作、专属技能与声音完善全部后置，不再阻塞主线。** 已有选角与可用英雄保留；本次没有要求移除阵容或锁死游戏选项。停止继续打磨 A-86 梦比优斯候选，已下载文件、工具、失败证据和未完成项保留，最后统一恢复。

按以下顺序推进，每阶段以可见体验和实际流程问题驱动修改：

1. **一局的引导与衔接**：迪迦入场／变身 → 远近战 → 怪兽预警／防御或受击恢复 → 满能必杀 → 胜利 → 自动合照预览 → 放手后举手再来一局。语音给足反应时间；全程不需要键鼠；同一举手不能跳过下一阶段。
2. **整段战斗演出**：集中改善迪迦与哥尔赞的动作连续性、发力、距离变化、冲击、镜头与音效配合；使用同输入整段前后视频，避免只用单张漂亮截图验收。
3. **合照与收尾体验**：固定迪迦比例、人物缩放稳定、预览和保存一致；真人抠像／融合效果与续局提示一起验证。AI 美化不得卡住再玩一局。
4. **迪迦版本交付验收**：构建可试玩包，连续完成三局、合照／重拍／续局／断流恢复；随后补真实孩子＋小米电视验证。合成回放不替代现场；新问题修复后再关闭里程碑。

此里程碑完成后，再恢复其他英雄与阵容扩展。60 FPS／5 GB 内存专项仍按此前要求后置；若发现崩溃、持续泄漏或影响主线的卡顿，则及时处理。角色数量和未补齐的其他英雄原声，不作为迪迦里程碑的完成条件。总项目仍包含这些后置工作，**不因调整顺序提高 70.2% 的总进度**。

## 看板目的

这张表把“当前已经可玩”和“距离参考街机仍有差距”分开记录。百分比是项目管理口径，不是对商业街机画质的主观认证；它按任务权重和验收证据计算，素材缺失时不能用占位图把进度记为完成。

## 进度口径

每项任务有一个权重 `W` 和完成度 `P`（0、25、50、75、100）。当前 11 项任务的权重合计为 105；项目完成度按总权重归一化：

```text
项目完成度 = Σ(W × P / 100) / (ΣW / 100)
```

当前按下面的保守估计为 **70.2%**（加权点 73.75 ÷ 总权重 105）。这个数字表示看板中已完成的实现与证据比例；不能解释为“已经达到参考视频的商业画质”。本轮保持 ARCADE-10 为 95%，因为发行版窄流程已用真实 loopback pose stream 确认“单手切换到可用英雄 → 放下手 → 双手变身”不会跳过选角；真人儿童和小米电视现场仍未验收。ARCADE-50 保持 75%，本轮新增角色优先舞台灯光证据，但完整电视亮度、模型精度和参考视频的整体连续演出仍未验收。ARCADE-90 保持 75%，发行包已完成三轮连续无键鼠整局、自动合照/重拍/再开局和同进程 RSS/VSZ 采样；角色切换、Unity reserved/稳定帧率和真实现场仍未验收。ARCADE-70 保持 75%，人物蒙版、边缘保护、合成网关调用和发行回放均通过；仍只用合成测试图，真人照片现场未验收。ARCADE-40 保持 75%，保留斜向失衡落地，并接入五英雄真人动作捕捉起身与前伸待战衔接，15/30/60 Hz、发行实战和完整合成体感续局通过；真实儿童、真实摄像头和小米电视现场仍未验收。后续拆分或合并任务时必须同步调整总权重和公式，保持分母明确。阻塞的外部素材任务按实际可交付范围计分，未取得模型、音乐或原声时保持未完成。

## 多任务并行、冲突与状态定义

本看板是任务、依赖、权重、完成百分比和当前基线的唯一来源；差距审计、改动索引和验证记录只回链这里，不另算总体进度。

- **领取**：每项任务先登记负责人、`codex/<task-id>-<slug>` 分支或 worktree、锁定文件、依赖、验收命令；未登记的任务不能并行修改共享入口。
- **并行**：不同任务只能修改各自声明的文件边界。`ArenaController.cs`、`RiggedActor.cs`、`HeroRoster.cs`、`HeroSelection.cs`、`PhotoComposition.cs` 和追踪文档是高冲突文件，同一时刻只由一个任务持有编辑锁；需要跨边界时先交接接口或由集成者修改。
- **合并**：先更新到本看板基线；只解决本任务范围冲突，不覆盖另一任务证据。集成后必须运行 `git diff --check`、`bash scripts/check.sh`、相关 Unity 构建和至少一次整局回放，再在看板和 [`改动索引.md`](改动索引.md) 追加提交与证据。
- **状态**：`Planned` 未开始；`In progress` 已领取开发；`Blocked` 等待依赖/素材/授权/环境；`Review` 已提交但专项验收未齐；`Done` 依赖、验收、提交和索引齐全。没有证据不得从 `Review` 直接改为 `Done`。
- **历史状态映射**：总览表中既有的“已完成”按 `Done` 解释，“基本完成”按 `Review` 解释，“进行中”按 `In progress` 解释，“进行中/部分阻塞”“素材依赖”按 `Blocked` 解释，“待专项窗口”按 `Review` 解释；新任务记录统一使用上面的五个英文状态。
- **百分比**：只按表中权重 `W` 和完成度 `P` 计算 `Σ(W × P / 100) / (ΣW / 100)`；文档整理、重复验证和审计本身不提高 `P`；外部素材或现场验收未完成时保留实际完成度。

## 并行开发拆分

每个可并行任务必须使用独立分支或 worktree，分支名建议为 `codex/<task-id>-<slug>`。任务完成后先运行自己的最小验证，再由集成者按依赖顺序合并。下面的拆分按“一个任务一个主要所有权目录”设计：

| 批次 | 可并行任务 | 允许修改的主要目录/文件 | 不应同时修改 |
| --- | --- | --- | --- |
| Batch A：资料 | ARCADE-01、ARCADE-30（素材审计部分）、ARCADE-60（来源审计部分） | `docs/**`、新资源自己的 `Assets/Resources/Characters/<id>/**`、资源说明 | `HeroRoster.cs` 和共享选择 UI 由集成者统一改 |
| Batch B：表现 | ARCADE-20、ARCADE-40、ARCADE-50 | HUD/镜头、动作运动类、特效/场景脚本和 shader | 不要跨任务同时编辑 `RiggedActor.cs`；需要时拆成短提交后由集成者手工合并 |
| Batch C：体验 | ARCADE-10、ARCADE-70、ARCADE-80 | 姿态/状态机、合照脚本、设置 UI | `ArenaController.cs` 是高冲突文件，按函数区块预约或由一个集成任务修改 |
| Batch D：质量 | ARCADE-90、ARCADE-99 | 性能脚本、检查脚本、测试、`docs/验证记录.md` | 不要在性能分支改战斗规则或资源命名 |

### 冲突预约规则

1. 开工前在本文件的任务行填写负责人、分支、开始时间和“锁定文件”；同一文件只能有一个进行中的负责人。
2. `RiggedActor.cs`、`ArenaController.cs`、`HeroRoster.cs`、`HeroSelection.cs`、`PhotoComposition.cs`、`docs/验证记录.md` 属于高冲突文件。它们只能由一个任务直接编辑，其他任务通过新增独立类、资源或补丁说明交付。
3. 资源任务只提交自己的目录和 `ATTRIBUTION/许可证/哈希`，不覆盖其他角色资源，不把其他角色模型复制为占位。
4. 不跨任务重排或格式化大文件；每个提交只包含一个任务 ID 的相关改动。冲突解决后必须重新运行冲突两边的验证。
5. 合并顺序：资料/接口 → 核心状态机 → 动作与镜头 → 特效与音频 → 合照 → 性能 → 全量回归。任何任务依赖未合并的接口时保持 `Blocked`，不复制代码绕过依赖。

# 拳迹与爪迹柔化（2026-09-27）

对照根目录街机录屏的连续出拳段落，以及上一轮赛罗实际游戏近景，当前手部拖尾有明显的硬边三角片。旧实现以少量手部位置直接拼接宽带；伸拳转收拳时带面方向反转，短距离移动也会撑开很宽的面。

这次修改共享拖尾的几何与着色器，适用于五位英雄和哥尔赞双爪：

- 对已记录的手部轨迹做有界平滑插值，端点仍停在真实手部位置。
- 收拳转向时保持带面两侧方向连续，避免交叉；宽度受实际运动长度限制，两端收尖。
- 缩短保留时间，减少宽亮面，使用细亮核、淡光晕以及纵向渐隐。深度遮挡仍生效，远侧光迹不会穿过整个身体。

改动仅在 `StrikeTrails.cs` 和 `StrikeRibbon.shader`。攻击动作、伤害与命中时点、镜头、识别门槛、默认 50 次普攻血量、15 次普攻蓄满、语音后 3 秒反应时间保持原样。帧率专项继续后置。

## 对照与验证

本机 `artifacts/strike-ribbon/index.html` 包含两个同步对照视频、五位英雄的左右拳接触帧。左侧基准为 `08db79b`，右侧为新版。

- `comparison.mp4`：16 秒、480 帧，左右拳各两次、左右爪各一次、一次格挡和一次受击。
- `roster-comparison.mp4`：梦比优斯左右拳及收势，2.5 秒、75 帧。

两侧采用相同输入、随机种子和镜头。每侧源图 1280×720，拼接编码为 1920×540 / 30 fps，无声；这是离线演出对照，不是实时帧率。前后源码摘要分别保存在 `before/render-source.txt` 和 `after/render-source.txt`；已逐项核对前者与基准提交、后者与当前源文件一致。五英雄帧保存在独立的 `artifacts/strike-ribbon-roster`，共享拖尾摘要以本轮 Exchange 记录为准。

`logs/strike-ribbon-after.log` 验证了主手端点绑定、左右攻击均有拖尾、待机不残留，以及整局重置清理。在四个攻击采样点中，关闭拖尾后可见差异像素为 312 / 591 / 4212 / 619，说明并非直接隐藏效果来消除三角片。这项检测只证明被采样画面中有可见拖尾，不单独作为美术品质的结论。

`logs/strike-ribbon-interruptions.log` 通过有效拳迹中暂停、重置和恢复后的残留检查。`logs/strike-ribbon-roster-after.log` 验证五位英雄各两次命中；接触间距及护手测量与修改前一致。已人工查看迪迦、赛罗和格力乔接触画面及怪兽爪击画面。

`logs/strike-ribbon-check.log`：33 项 Python、300 项 C# 核心检查及 3 项额外回环检查通过。`logs/strike-ribbon-build.log`：macOS 构建和本地签名通过。

## 复现

```sh
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.ExchangeReview.After \
  --exchange-output "$PWD/artifacts/strike-ribbon" \
  -quit -logFile "$PWD/logs/strike-ribbon-after.log"
```

五英雄复核使用 `RosterPunchReview.After --roster-output "$PWD/artifacts/strike-ribbon-roster"`；暂停与重置使用 `ExchangeReview.Interruptions`。这些命令重建 after，不覆盖 before。

本次改善的是挥动光迹。怪兽攻击时另外的橙色爪痕、源模型细节和有限的长段动作编排仍需改进，当前版本尚未达到参考街机的最终表现。

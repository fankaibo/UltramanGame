# 远程连发连续镜头

A-20261010-70，2026-10-10。镜头实现 `db7f13a`，发行取证 `65d2cde`，体感轨迹验证 `06c268d`，旧版对照 `8b74fd5`。

## 参考与改动

复看本机参考录屏 52–56 秒，连续出手期间角色保持主要视觉位置，光效和身体动作形成一个连续段。视频不能证明街机内部的镜头算法；本实现针对电视横屏重新设计。

旧版把远程技能送入近战的逐拳镜头：每次向前偏移、根据左右手横移，再回零。现在单发只做小幅靠近；接续远程攻击时，缓慢推进到中近景，并保持同一侧的轻微横移。停手后平滑回到宽景。连发期间允许英雄的部分小腿出画，优先完整呈现头部、双手、怪兽和光弹通道；防御、近战和预警恢复各自的构图，必杀仍使用专属镜头。

镜头只观察已接受的攻击，不生成输入、不改变伤害、攻速或提示时长。连续镜头使用独立平滑时钟；暂停、新局、展示、受击和必杀清除它。返回途中重新出手时保留当前横移方向，避免翻边；重置后不会重复使用已经消费的攻击。

- 连发峰值角色投影相对中性机位约 1.328 倍；旧版逐拳峰值约 1.071 倍。不能把它解释为画质提高 33%。
- 连续段 2–4 秒的相机横坐标摆幅由约 0.586–0.587 降为 0.081–0.088 场景单位。平滑推进的最大相机速度约 8.8–9.1，仍大于旧版短幅摆动的约 5.0–5.2；这里改善的是构图连续性，而非宣称所有镜头运动都更少。

- 27 组 15/30/60 Hz 生命周期覆盖防御、普通近战、第五击、怪兽预警、暂停、F5、新局、重置和必杀。防御／近战／预警交接最大速度约 6.8–10.2；暂停和必杀等保留原先明确切镜头的行为，不以连续运动速度验收。
- 41 Python + 980 核心检查通过。现有自然前伸手位、识别和其他战斗规则没有改动。

## 检查中的修正

首轮核心测试在怪兽预警刚出现时就要求镜头已经退出，错误地省略了软退出时间。改为从事件出现开始计时，验证退出过程后通过，没有降低退出精度。

首轮背景检查把普通战斗的边距要求套到新局 37° 的等待机位。另行测试完全未进入连发的机位，背景角点为 0.49123，仍在半宽 0.5 的背景内部；生命周期检查改为实际覆盖加 0.001 边距，战斗场景原来的 0.49 上限保持不变。该过程没有改动背景或掩盖露边，日志保留于 `logs/ranged-camera-lifecycle.log` 与 `ranged-camera-waiting-coverage.log`。

前两轮发行回放均到达合照与下一局，但未出现连发峰值，镜头专项因此失败。日志确认原 `tempo_landmarks` 的胸前收拳，以及第一次补充轨迹的较低收手位置，仍处于识别器宽容的护盾范围；镜头正确让出防御。两次证据分别保留于 `guided-initial-guarded/` 和 `guided-low-guarded/`，没有放宽镜头断言、忽略护盾或修改生产识别逻辑。

最终 `--volley-camera` 补入一段六次交替前向挥拳，非出拳手自然下垂；之后继续原慢快出拳、明确防御、大招和完整合照流程。先把同一 Python 轨迹交给生产 C# 识别器和战斗／镜头时钟离线检查，确认 6 次命中、0 帧护盾、镜头达到峰值，证据 `fixture-check/frames.jsonl` 和 `result.txt`。这一补充区分“连续攻击”和“攻击之间主动防御”，而非为通过画面检查改变玩法。

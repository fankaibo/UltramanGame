# 防御准备与生效提示（A-20261019-185）

基线 `432a27a`，对应第一条“迪迦整局引导与衔接”的快速迭代。

## 问题与改动

原预警提示把 `GuardIntent` 与真正生效的 `battle.Shield` 合并称作“护盾姿势已锁定”。候选姿势尚在确认时，这会让孩子误以为已有保护；非预警阶段，防御候选还可能继续显示开场出拳提示。

现在按实际状态呈现三个阶段：双手交叉护在胸前或脸前 → 看见防御姿势、保持一下 → 护盾已展开、保持住。候选与展开共用原识别进度条，非预警防御也接管旧出拳提示。已开始的大招保持与怪兽预警保留原有优先级；键盘模式继续显示 S 键操作。

修改 `CameraGuidance.cs`、`ArcadeHud.cs`，在 `GuidedProof.cs` 增加仅限合成验收的截图事件，`CameraGuidanceChecks.cs` 覆盖标准难度下 15／30／60 Hz 从放手到防御、实际护盾、切大招和释放后的提示。没有调整姿势阈值、伤害、敌人时钟，也没有加入手势选英雄。

## 验证与交付

`bash scripts/check.sh`：58 项 Python 测试和 2462 项检查通过。早期测试错误地要求宽松模式在 15 Hz 下必有候选帧，但该模式保持门限只有 50ms；修正测试为标准难度及实际放手到防御流，运行时难度未改动。

源码 Release 构建及签名通过；174 个源码／着色器哈希与包载荷记录在 `artifacts/a185-guard-guidance/build.json`。实际运行包截图已检查：`guided/native/guard-guide-hold.png` 是 59% 的候选确认且尚无护盾，`guard-guide-active.png` 是 100% 确认、护盾显示并提示已展开。不是仅凭日志推断画面。

实际发行包用合成摄像头输入完成 165.1 秒整局：2098 个普通战斗输入帧全部为高位，32 次左右光弹命中，胜利、两张全身合照、重拍、断流恢复及下一局开始均通过。0 键鼠事件、0 手势切英雄；两张照片的预览保存误差均为 0。重拍／续局分别在预览 4.80／4.92 秒、语音仍播放时接受，放手后举手语音交接为 0.973 秒。

核对源文件与包载荷后，整包更新默认 `unity/Builds/TigaTraining.app`，上版保留为 `TigaTraining-pre-a185.app`；`build.json`、`promotion.json`、`guided/guided-validation.json` 保存核验证据。

本轮不提高主看板 70.2%；合成输入不能代替孩子和小米电视的现场体验验收。

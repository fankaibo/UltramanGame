# 交替拳预备与连续衔接

快速左右交替出拳时，已有输入缓冲会接收下一拳，但角色仍先回到普通护手姿势，再从原点开始。现在只对已经接收的另一侧出拳增加预备：上一拳收回时，另一只拳收向肋侧，肩部小幅旋转，动作跨过两拳之间的一帧空闲状态，再在命中前释放。

`HeroPunchLink` 只读取战斗状态，不生成输入，也不修改伤害、能量、出拳间隔或识别阈值。普通拳仍为 0.38 秒，命中仍在 0.12 秒；没有收到下一拳时不会自动连击。护盾、必杀、受击、暂停、新的一局及角色预览都会结束预备。

五位角色均复用这层肩部与手臂预备。第一次画面对照中，拳收得过高且过近，肘部折叠不自然；最终调整为稍向后、向内、向下收拳，转肩幅度从 12 度降至 10 度。脚部支撑与已有第五拳勾拳、第十拳上勾拳继续沿用已有动画。

## 验证

- 基线 `788f2d6f821eb0edb7ddcb255586c0aec34b8ad1` 与当前实现各渲染 4 秒、120 张画面。240 个模拟战斗状态逐字节一致，6 次命中时出拳手位置差为 0；这证明预备没有改变接触结果，不表示现有接触动画已经完美。
- 五位英雄各用 15／30／60 Hz 逻辑步长，均完成 6 拳、5 次预备衔接、50→44 点血量。检查零时间重复采样、命中时预备归零、单拳不预测下一拳及暂停／防御／新局取消。
- `scripts/check.sh`：36 项 Python 测试，348 项 C# 核心检查，含跨进程协议的 351 项检查通过。
- 最终打包版的 `--review-linked` 只改变开发回放的前几次出拳输入，让实际应用走过缓冲衔接。96.94 秒完成全局回放：32 次普攻、2 次必杀、3 次防御、1 次受击、暂停恢复及胜利；实际画面包含收拳预备与下一拳衔接。
- 同一程序用真实姿势接收器回放 138.1 秒，无键鼠输入：97 帧防御噪声、10 帧大招噪声期间误触普攻为 0，防御和大招各 2 次。自动合照两次、重拍、照片流与姿势流中断恢复、举手续局并重新进入战斗均通过。预览与保存照片中心区域的颜色差 P99 为 0。

## 复现

`PunchLinkReview.Before` 必须在基线运行，保留 `before` 目录，再切换到当前源码运行 `After`；不要用当前代码覆盖旧版证据。

```sh
Unity -batchmode -projectPath "$PWD/unity" \
  -executeMethod UltramanGame.Editor.PunchLinkReview.After \
  -quit -logFile "$PWD/logs/punch-link-after.log"
bash scripts/check.sh
bash scripts/build_macos.sh
.venv/bin/python scripts/cinematic_player_check.py --hero Tiga --slam --ray --linked
.venv/bin/python scripts/guided_player_check.py --gesture-wobble \
  --output artifacts/punch-link/guided --log logs/punch-link-guided.log
.venv/bin/python scripts/encode_punch_link_review.py
```

本次改善范围是连续拳的衔接。防御／大招的冲突修复见《姿势冲突与合照效果复核》，AI 合照现有能力及限制见《合照线性光色与接触阴影》。整体动画与合照质量仍需继续提升，不能据此认为已经达到参考视频的街机效果。

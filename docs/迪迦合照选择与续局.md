# 迪迦合照选择与续局（A-20261010-88）

基线 `c894f23`；按用户“先完成迪迦整局”的安排处理收尾流程，其他英雄候选继续后置。

## 问题与修改

旧发行日志 `logs/fighter-framing-guided.log` 的两次合照均有 `choiceReadyIn=8.80s` 左右：整个 `photo_saved` 播报时长加缓冲锁住菜单，孩子已放手后主动举手仍必须等待。新版本只保留 2.5 秒照片展示时间，之后已有放手动作的孩子可以在播报中主动重拍或再玩一次。单手仍需保持 2 秒，双手仍需 1.2 秒；过期画面、长期断流以及一直保持拍照姿势都不能直接触发。

合照底部增加独立的单手“重拍一张”、双手“再玩一次”图示。候选动作高亮，进度显示在对应选项上；尚未放手时继续显示放手提示。没有在保存到 Downloads 的照片上添加这些控件。原有 `Speak` 高优先级规则会在重拍时用新引导替换旧播报；续局仍走 `Restart` 的清空语音与放手重置，未添加额外语音等待。

本次不修改战斗伤害、50 次默认血量、15 拳能量、战斗动作与识别阈值，也没有替换角色模型。AI 处理不拥有菜单解锁条件。

## 实际回放发现的第二个断点

首轮 `guided/` 回放已在播报中完成重拍（4.88 秒）与续局（4.95 秒），但新加入的“同英雄、保持举手”检查失败：`Held photo replay gesture skipped fresh release before transformation`。原先续局测试先放手六秒再切换英雄，因此没有覆盖这个分支。失败日志和截图保留，不计为验收通过。

根因是 `Restart()` 设置了放手门槛后清空 `pose`；下一个摄像头包到达前，`ArenaController` 的空帧分支又调用无参 `Reset()`，把门槛清掉。现拆出 `GestureRecognizer.ResetTracking()`，只清理旧输入和运动历史；相机丢帧、无效数据、设置关闭及输入模式切换均使用它，保留新局的放手门槛。只有看见实际放下双手的有效姿态才解除。首次启动仍允许直接举手进入，未增加孩子的持姿难度。

## 验证范围

- 新增核心检查：八秒播报过程中，完成释放后的单手／双手可选择；一直举手仍不可选择。原有断流、相机裁切、换流和新局重置检查保留。
- 新增四项续局回归：开局连续空帧、追踪丢失／换流不能代替放手；恢复后真正放手可进入；首次启动不误加放手要求。
- 实机回放新增 `--early-photo-choices`：要求重拍和续局确实在语音仍播放时触发，并取得两种选择的实际进度截图。
- 新增 `--same-hero-replay`：合照续局后先故意保持双手举高，再放下、重新举起；保持阶段不得跳过 Waiting，第二局必须仍是同一个英雄。本轮使用迪迦；此模式不冒称覆盖了“换英雄”分支。
- 输入、人像均为合成测试资料，不能证明真实儿童手势准确率或电视延迟。试玩与整段演出的总体目标仍未完成。
